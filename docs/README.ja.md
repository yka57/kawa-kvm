# NanoKVM-USB ブラウザー版 — kawa フォーク ガイド

Mac（MacBook のトラックパッド、日本語環境、Chrome）から NanoKVM-USB 経由で Windows 機を操作するための個人フォークです。upstream（[sipeed/NanoKVM-USB](https://github.com/sipeed/NanoKVM-USB) の `browser/`）に次の 3 つを足しています。設定を何も触らなくても変わる点は「[upstream からの挙動変更](#upstream-からの挙動変更)」にまとめました。それ以外の HID レポートは upstream とバイト単位で同一です。

公開ページ: **https://yka57.github.io/kawa-kvm/**（「[Mac で動かす](#mac-で動かす)」参照）

| 機能                                                                                                                                                                                                                       | 場所                                                          | 既定値                                                      |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------- |
| **⌘ キー変換** — ⌘C/V/A/F/X/Z は Ctrl、それ以外の ⌘ は Win として送信（⌘⇧S = Win+Shift+S）＋ Mac 風ナビゲーション                                                                                                          | キーボード → ⌘ キー変換（Mac）                                | **オン**（Mac ホストかつ操作先 OS が macOS 以外のとき有効） |
| **トラックパッド / スクロール** — 2 本指スクロールを移動量に比例させる、ボタンが押しっぱなしにならない絶対座標、相対座標のポインター速度                                                                                   | マウス → ホイール速度 / ポインター速度                        | スクロール感度 100 px/ノッチ、ポインター速度 ×1.00          |
| **クリップボードを入力** — Mac のクリップボードを操作先にキー入力として打ち込む（US / JIS 配列対応、ASCII 以外（日本語など）を含むテキストは Windows ではブラウザー経由・Linux では Ctrl+Shift+U、進捗表示、いつでも中断） | キーボード → クリップボードを入力（⚙ = 設定）、ホットキー ⌘⇧V | 速度「標準」、改行 = Enter、日本語など = 自動、⌘⇧V 有効     |

あわせて、共通設定の「操作先 OS」「操作先のキー配列」、日本語 UI（日本語のブラウザーでは自動選択）、「全キーを離す」、HID ログ（`?debug=hid`）を追加しています。

## Mac で動かす

**一番簡単なのは公開ページを開くことです。** `main` に push するたびに GitHub Actions（`.github/workflows/pages.yml`。`npm run build:pages` = `build` に `--base=/kawa-kvm/` を付けたもの）がビルドして次の URL に公開します。

**https://yka57.github.io/kawa-kvm/**

NanoKVM-USB を Mac に挿し、Chrome でこの URL を開いてカメラとシリアルポートを許可するだけです。Mac には何もインストールしません。ページは Chrome の中で動き、Mac の USB 経由で直接デバイスと通信します。サーバーは静的ファイルを渡すだけです（`https://` はセキュアコンテキストなので WebSerial が使えます）。新しい版を反映するにはページをリロードします。

**ローカルで動かす場合:** WebSerial とカメラは **セキュアコンテキスト**（`https://` または `localhost`）でしか使えません。NanoKVM-USB を挿した Mac 上で開発サーバーを起動し、`localhost` で開きます。

```shell
git clone https://github.com/yka57/kawa-kvm.git   # または rsync でフォルダーを Mac にコピー
cd kawa-kvm
npm install
npm run dev                 # Vite が http://localhost:3001 で起動
```

Chrome で **http://localhost:3001** を開きます（WebSerial は Chromium 系のデスクトップブラウザーのみ）。`http://localhost` はセキュア扱いなので、シリアルとカメラの許可ダイアログが出ます。

**LAN の `http://` オリジンはセキュアコンテキストではありません。** 別のマシンから `http://192.168.x.x:3001` で開くと「シリアル非対応」になり、カメラも使えません。別マシンから使う場合は **HTTPS** で配信するか、デバイスを挿したマシン上で **localhost** を使ってください。`npm run build && npm run preview` を使うと本番ビルドを http://localhost:4173 で確認できます。

必要なもの: Node 22（Vite 7 は 20.19 / 22.12 以上）、npm。

## 機能と設定

### 共通設定（キーボードメニュー）

| 行               | 選択肢                   | 既定値                             | 使われる場所                                                                                                                                           |
| ---------------- | ------------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 操作先 OS        | Windows / Linux / macOS  | Windows                            | macOS を選ぶと ⌘ キー変換が無効になります（⌘ はそのまま ⌘ として届きます）。貼り付けの「自動」（日本語などの入力方法、IME オフキー）もこれで決まります |
| 操作先のキー配列 | US (ANSI) / 日本語 (JIS) | UI が日本語なら JIS、それ以外は US | クリップボード入力の記号の変換表、Caps Lock を自動でオフにするキー（JIS は Shift+CapsLock）                                                            |

### ⌘ キー変換（Mac）

Mac ホストでのみ表示されます。有効になる条件は「ホストが macOS **かつ** オン **かつ** 操作先 OS が macOS 以外」です。upstream では ⌘ は Win キーとして送られるため、⌘C は Win+C、⌘ を単押しするとスタートメニューが開いていました。

**オン時の動作**

- **振り分け（既定オン）**: ⌘ を押しただけでは何も送らず、一緒に押したキーで決めます。「Ctrl にするキー」（既定 `ACFVXZ`、英字・数字を並べて変更可）なら Ctrl＋キー、それ以外は Win＋キー（⌘⇧S = Win+Shift+S のスクショ、⌘R = Win+R など）。⌘ だけを押して離すと Win の単押し（スタートメニュー）。⌘L は Win+L（画面ロック）になるので注意。振り分けオン時は ⌘クリック・⌘＋ホイールに修飾キーは付きません。
- 振り分けをオフにすると v1 と同じく、左右の ⌘ → 左右の Ctrl（⌘ の単押しは Ctrl の単押し）。
- ⌃ は Ctrl のまま、⌥ は Alt のまま。
- ⌘ を押している間に押したキーは **短いタップ**（押下 → 50 ms 後に自動で離す）として送られます。macOS の Chrome は ⌘ 押下中の keyup を届けないため、押しっぱなし（Ctrl+V の連打）を防ぐ仕組みです。キーを押し続けるとホストのオートリピートで再タップされるので、⌘V を 2 秒押せば貼り付けが繰り返され、離すと止まります。⌘C を素早く押して離しても送られます（最短 30 ms）。
- ⌘⇧V は（ホットキーが有効なら）操作先に送らず「クリップボードを入力」を起動します。

**チェックボックス**

| 項目                       | 既定 | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Mac 風ナビゲーションも変換 | オン | ⌘←/→ → Home/End、⌘↑/↓ → Ctrl+Home/End（Shift はそのまま: ⌘⇧← で行頭まで選択）。⌥←/→ → Ctrl+←/→（単語移動。変換しないと Alt+← = ブラウザーの「戻る」）、⌥⌫/⌥⌦ → Ctrl+⌫/⌦。⌘⇧[ / ⌘⇧] と ⌘⌥←/→ → Ctrl+Shift+Tab / Ctrl+Tab（タブ切り替え。全画面時のみ届きます）                                                                                                                                                                                    |
| 英数/かな → 無変換/変換    | オフ | オフのときは、JIS Mac の 英数 / かな が LANG2 / LANG1 のまま届き、Windows 10 2004 以降 / 11 の日本語キーボードでは IME オフ / オン になります（Mac と同じ使い方）。オンにすると 英数 を 無変換、かな を 変換 として送信します。操作先の MS-IME で「無変換 = IME オフ、変換 = IME オン」を割り当てている場合だけ正しく動きます（既定のキーテンプレートでは無変換はかなモードの切り替えです）。1 回試してから決めてください（TESTING.ja.md の Q1） |
| Caps Lock の同期を補正     | オン | macOS はロックオン時に keydown、オフ時に keyup を出すので、両方で Caps Lock を 1 回タップして操作先と同期させます。オフにすると upstream と同じ（オン時しか届かず、ずれる）                                                                                                                                                                                                                                                                      |

UI のない項目（`nanokvm-usb-keyboard-remap` の JSON を直接編集）: `tapReleaseMs` 50（20〜200）、`minPressMs` 30（0〜100）、`repeatUnderMeta` true。

**送信できるショートカット**（ヘルプ「送信できるショートカット」に同じ一覧があります）

- 通常ウィンドウで届く: ⌘C/V/X/A/Z/⇧Z/F/S/R/P/L/D/1…9/+/−/0、⌘←/→/↑/↓、⌥←/→、⌥⌫
- **全画面＋キーボードロック時のみ**（ヘルプの「全画面にする」ボタン、またはメニューの全画面）: ⌘W/⇧W/T/⇧T/N/⇧N、⌘⇧[ / ⌘⇧]、⌘⌥←/→、⌃Tab
- 届かない（OS が先に取る）: ⌘Tab、⌘Space、⌘Q、⌘⌥Esc、⌘⇧3/4/5 → 「ショートカット」から送ってください。既定の行: Win+Tab、Ctrl+Alt+Del、Alt+Tab、Ctrl+Shift+Esc、Win（不要な行は「カスタム」を開き、下の「標準のショートカット」のチェックを外すとメニューから消えます。チェックを戻せば復活します）

**キーテスト**（ヘルプの下部）: 開いている間はキーが操作先に送られません（ドライラン）。最新 6 件の `種別 · code · key · repeat · ⌘⌃⌥⇧ → 送信した HID コード + レポート hex` と「⌘ 押下中に届いた keyup」の回数が出ます。右下の「HID ログ」リンクで HID ログを開けます。

**関連する動作**

- ショートカットの記録モーダルに「⌘ を Ctrl として記録」が出ます（変換が有効なときに表示。振り分けオン時は既定オフ＝ ⌘ は Win として記録、振り分けオフ時は既定オン）。⌘⇧T を記録すると Ctrl+Shift+T として保存されます。
- 「全キーを離す」行: キーボードの全キーとマウスの全ボタンを離すレポートを送ります（何かが押しっぱなしになったとき用）。
- 変換が有効でシリアル接続中は、タブを閉じる・再読み込みすると確認ダイアログが出ます（⌘W/⌘Q は Chrome が先に処理するため、うっかり閉じないように）。
- 変換は物理キーボードの経路だけに効きます。仮想キーボードとショートカットは記録されたコードをそのまま送ります（Win は Win のまま）。

### トラックパッド / スクロール

**絶対座標モード（既定）**

- マウス / ペンは Pointer Events とポインターキャプチャで処理します。動画の外でボタンを離してもボタンアップが送られ、ウィンドウが非アクティブ・タブが非表示になったときも全ボタンを離します。
- 座標は表示の余白（レターボックス）と回転（90/180/270°）を考慮して 0〜4095 に変換します。右端・下端は 4095 です。
- タッチ操作は upstream のままです。

**スクロール（両モード共通）**

- ホイールイベントの px を積算し、`スクロール感度` の px ごとに 1 ノッチ送ります（既定 100 px。スライダー 0 ↔ 400 px、60 ↔ 100 px、100 ↔ 40 px）。
- ジェスチャーの最初のノッチは 3 px で発火（短いナッジで必ず 1 ノッチ）、2 px 以上の逆方向で即座に逆ノッチ、200 ms 以上の間隔で新しいジェスチャー扱い。横方向が主の 2 本指操作は送りません。
- 「ホイール速度」（upstream のスライダー）はノッチ間の最短間隔です（既定 = 最速 = 制限なし）。間隔内のノッチは捨てられます（upstream と同じ意味）。
- 1 レポートあたりのノッチは ±127 に制限します。

**相対座標モード**

- 動画をクリックするとポインターロックを要求します。このクリックは操作先に送られません。ロック中以外は移動・クリック・ホイールを一切送りません。ロックに失敗したら案内が出ます（再クリックで再試行）。
- `ポインター速度`（相対座標モードでのみ表示）: 倍率 0.25〜4（既定 ×1.00、スライダー 50）。端数は持ち越すので、ゆっくり動かしても取りこぼしません。upstream の「小さい移動量を 2 倍にする」ルールは廃止しました。
- 大きく振ると ±127 を超える分を複数レポートに分割して送るので、移動距離がそのまま届きます。Esc などでロックが外れると押しているボタンを離します。

**移動レポートの間引き（coalescing）**

シリアルへの書き込み中に新しい移動が来た場合、絶対座標では最新の位置だけを残し（古い位置は捨てる）、相対座標では移動量を合算して、書き込みが終わった時点で送ります。ボタン・ホイール・全解除のレポートは捨てず、順序も保ちます。キーボードのレポートは対象外です。

**貼り付けの実行中**は、移動とホイールのレポートを送りません（絶対座標・相対座標・タッチとも。トラックパッドの慣性スクロールも含む）。ボタンの押下と解放は送ります（押下は貼り付けを止めます）。「[クリップボードを入力（貼り付け）](#クリップボードを入力貼り付け)」の「進捗と停止」を参照してください。

**マウスジグラー**: 15 秒操作がないと ±10 px 動かす機能は、upstream ではキーボードのフレームとして送られていて動いていませんでした。相対マウスのフレームで送るよう直しています。

### クリップボードを入力（貼り付け）

**使い方**

1. Mac 側でテキストをコピーする。
2. 操作先で、貼り付け先の欄をクリックしておく。操作先が Windows なら、ASCII 以外の文字が 1 つでもあるとテキスト全体がブラウザー経由になるので、Chrome / Edge / Firefox の中の欄にします。日本語に限らず、é ° • → × などの記号や見えない文字でもそうなります（「記号を正規化」がオンなら、ゼロ幅スペースなどよく混ざる見えない文字は先に取り除きます。下の「入力方法」と「ブラウザー経由に必要な条件」参照）。
3. キーボードメニュー → 「クリップボードを入力」をクリック（または ⌘ キー変換がオンなら **⌘⇧V**）。
4. 操作先でキー入力として打ち込まれます。実行中は同じ行が「キャンセル」になり、⌘⇧V をもう一度押しても中断します。

クリップボードの読み取りがブロックされている場合は設定モーダルが開き、テキスト欄に貼り付けて「このテキストを入力」で同じ処理ができます（アドレスバーの鍵アイコンから許可することもできます）。ページをクリックしていないと読めない（`noFocus`）、空、シリアル未接続のときはトーストで知らせます。

**入力方法**

テキストを操作先のキー配列（US / JIS）のキーだけで打てるかどうかで決まります。

- 全部打てる（ASCII だけ。「記号を正規化」がオンなら、スマートクォートなどを ASCII に直し、見えない文字 U+00AD（ソフトハイフン）、U+200B（ゼロ幅スペース）、U+200C、U+200D、U+2060、U+FEFF を取り除いてから判定）: これまでどおり 1 文字ずつキーで入力します（直接入力）。
- 打てない文字が 1 つでもある（日本語、全角の記号、`¥`、絵文字のほか、é ° • → × などの記号や、上で取り除かない見えない文字）: 「日本語など（ASCII 以外）」の設定で決まります。既定の「自動」では、操作先 OS ごとに次のとおりです。

| 操作先 OS | 「自動」の方法 | 内容                                                                                                                              |
| --------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Windows   | ブラウザー経由 | テキスト全体（ASCII も含む）を操作先のブラウザーの一時ウィンドウに URL として打ち込み、コピーして元の欄に貼り付けます             |
| Linux     | Ctrl+Shift+U   | キーのある文字はそのまま打ち、それ以外は 1 コードポイントずつ Ctrl+Shift+U、16 進数、Space で入力します                           |
| macOS     | 入力しない     | 打てない文字はスキップして一覧を表示します。どちらの方法も Ctrl のショートカットを使うので、明示的に選んでも macOS には送りません |

ブラウザー経由と Ctrl+Shift+U は、コピーした文字をそのまま届けます。記号の正規化も Unicode の NFC 正規化もせず、見えない文字も残します。行うのは、先頭の BOM の除去、改行（CRLF / CR）の LF への統一、末尾の改行 1 つの削除（設定がオンのとき）、タブと改行以外の制御文字の除外だけです。下の IME コード入力と Alt＋テンキーも同じです。

Windows では、打てない文字が 1 文字でもあれば、ASCII の部分も含めてテキスト全体がブラウザー経由になります。たとえば `Set the oven to 180°C` は ° のためにブラウザー経由になり、標準で約 24 秒かかります。ブラウザー以外のアプリに入れたいとき、またはその文字がなくてもよいときは「入力しない（ASCII のみ）」にします。v1 と同じく、打てない文字だけをスキップして一覧に出し、残りを直接入力します（この例では `Set the oven to 180C` と入力され、° がスキップされます）。

Windows の操作先では、「自動」のほかに、ウィンドウを開かずに選択中の欄へそのまま打つ方法を 2 つ選べます。おすすめは「IME コード入力」で、操作先の準備は要りません（[IME コード入力（Windows）](#ime-コード入力windows)。Teams のデスクトップアプリそのものではまだ測定していないので、最初はメモ帳で試してください）。もう 1 つの「Alt＋テンキー」は、操作先のレジストリの設定が必要です（その次の節）。どちらも、キーのある文字はそのまま打ち、それ以外を 1 コードポイントずつ入力します。「自動」がこの 2 つを選ぶことはありません。

**入力前の IME と Caps Lock**（すべての方法で共通）

- IME: 「入力前に操作先の IME をオフにする」が「自動」なら、操作先 OS が Windows のときだけ IME オフキー（HID の LANG2 = 0x91）を 1 回送り、0.15 秒待ってから入力します。Windows 10 2004 以降 / 11 の日本語キーボードでは、Microsoft IME がどの状態からでもオフ（半角英数）になります。何度送っても同じで、古いビルドでは無視されるだけです。Linux と macOS には「自動」では送りません。ブラウザー経由では、開いたウィンドウのアドレスバーで（確認ページの前と本文の前に 1 回ずつ）送ります。無変換（0x8B）は既定の Microsoft IME では IME をオフにしない（かなの種類が切り替わる）ので、IME オフを割り当てた場合だけ選んでください。「日本語など（ASCII 以外）」が「IME コード入力」のときは、この設定に関係なく、最初に必ず IME オフキー（LANG2）を送ります。キーだけで打てるテキスト（ASCII だけなど）でも同じです（途中で止めると IME がオンのまま残ることがある方法なので、次の入力の前に必ずオフにします）。
- Caps Lock: 「操作先の Caps Lock がオンなら自動でオフにする」がオンなら、入力の前に機器（CH9329）から操作先のキーボード LED の状態を読みます。Caps Lock がオンなら、JIS では Shift+CapsLock（JIS では CapsLock 単独は 英数 キーのため）、US では CapsLock を送り、オフになったことを最大 1 秒で確かめます。オフにならなければ「停止: 操作先の Caps Lock をオフにできませんでした」で止まり、テキストは入力しません。状態を読めないとき（機器が応答しない、操作先が USB を認識していない）は何もしません。このチェックを外すと、設定の下の説明が「操作先で Caps Lock がオンの場合、英字の大小が反転します。」に変わります。そのまま操作先の Caps Lock がオンだと、直接入力では英字の大小が反転し、ブラウザー経由では確認ページが赤のままになって止まります（テキストは打ちません）。

**ブラウザー経由のしくみ**

ピルに今の段階と「完了まで操作しないでください」が出ます。コピーしたテキストは、確認ページが正しく表示されるまで 1 文字も打ちません。

1. 「ウィンドウを開いています」: まず映像から操作先の画面を読み取り（1 秒以内に読めなければ止まります）、0.3 秒おきに比べて画面が止まっている（変化が 2% 未満）ことを確かめます。2.5 秒たっても動き続けていれば止まります。動画やスクロールの慣性で画面が動いていると、ウィンドウが開いたかどうかを画面の変化で判断できないためです。ここまでは操作先に何も送りません。止まった画面を記録してから Ctrl+Shift+N（設定により Ctrl+Shift+P / Ctrl+N）で新しいウィンドウを開き、画面の 1 割以上が変わるまで最大 4 秒待ちます。0.6 秒待ってから Ctrl+L でアドレスバーに移り（Edge の新しいタブページでは、そのままだと入力が検索ボックスに行くため）、IME オフキーを送ります。
2. 「確認ページを開いています」（毎回）: `data:text/html,<body bgcolor=red><script>document.bgColor='magenta'</script>` を打ち込みます。ページは赤で始まり、スクリプトが動くとマゼンタになります。マゼンタが出れば、キーがブラウザーのアドレスバーに今のキー配列と IME のまま、英字の大文字・小文字も正しく届いています。テキストを打つ前にこれを確かめる手段はほかにないので、毎回開きます。操作先の Caps Lock がオンだと英字の大小が反転してスクリプトが動かず（`DOCUMENT` は存在しない）、赤のままです。赤ならこのページ（このアプリが開いたもの）を Ctrl+W で閉じて止まります。5 秒以内にどちらの色も出なければ、Ctrl+W を送らずに止まります（前面にあるのがこのアプリの開いたウィンドウとは限らないため）。マゼンタが出たら、もう一度 Ctrl+L と IME オフキーを送ります。
3. 「URL を入力しています」: テキストを入れたページを `data:text/html;charset=utf-8;base64,…` の URL として打ち込み、Delete（自動補完の候補を消す）と Enter を送ります。日本語 1 文字は URL では 4 文字（UTF-8 の 3 バイトの Base64）、ASCII 1 文字は約 1.3 文字になります。
4. 「内容を確認しています」: ページはテキストを入力欄に入れてハッシュ値を計算し、一致すれば背景を緑（lime）、違えば赤にします。緑を最大 6 秒待ちます（URL が 2,000 文字を超えると 2,000 文字ごとに 1 秒追加）。赤なら Ctrl+W でそのページを閉じて止まります。
5. 「コピーしています」: Escape（アドレスバーからページの入力欄へ）、Ctrl+A、Ctrl+C を送ります。ページはコピーを受け取ると、確かめたテキストそのものをクリップボードに入れ、背景を青にします。青を最大 1.5 秒待ち、出なければ止まります。このときは Ctrl+W も Ctrl+V も送りません（コピーできたか分からないまま貼り付けると、クリップボードに残っていた前の内容が入るおそれがあるため）。
6. 「ウィンドウを閉じています」: Ctrl+W で一時ウィンドウを閉じ、画面がウィンドウを開く前に戻るまで最大 3 秒待ちます（青が消え、1. で記録した画面との違いが 1 割未満）。OS が元のウィンドウを前面に戻し、ブラウザーが元の欄にフォーカスを戻します。戻らなければ止まり、Ctrl+V は送りません（別のウィンドウやタブに貼り付けないため）。
7. 「貼り付けています」: 0.3 秒待ってから Ctrl+V で元の欄に貼り付けます。

**ブラウザー経由に必要な条件**

- 操作先で、貼り付け先の欄が Chrome / Edge / Firefox の中にあり、フォーカスされていること。ウィンドウを開くキーは前面のアプリに届くので、ブラウザー以外では別の動作になります。メモ帳、Windows Terminal、VS Code は Ctrl+Shift+N で新しいウィンドウを開くため、確認ページの URL と Enter がそのウィンドウに打ち込まれ、「確認ページが表示されませんでした」で止まります（Windows Terminal では URL がコマンド行に入り、Enter で実行されます）。コピーしたテキストは 1 文字も打ちません。開いたウィンドウは保存せずに閉じてください。エクスプローラーでは新しいフォルダーができます。ほかのアプリに入れたいときは、いったんブラウザーの欄に貼り付けてください。テキストは操作先のクリップボードに残るので、目的のアプリで貼り付けられます。ASCII 以外の文字がなくてもよければ「入力しない（ASCII のみ）」にします。
- 映像が表示されていること。画面の変化と色で進み具合を確かめるためです。映像がないと「映像が表示されていないため、ブラウザー経由の入力は使えません」と出て、何も送りません（初回の確認の前と、開始の直前に確かめます）。
- 始める時点で操作先の画面が止まっていること。動画の再生、スクロールの慣性、アニメーションなどで画面が動き続けていると、ウィンドウを開く前に止まります。実行中はマウスの移動とホイールを操作先に送らないので、トラックパッドの慣性で操作先の画面が動くことはありません。
- 新しいウィンドウが HDMI の映像に映ること。複数モニターなら取り込んでいる画面で開き、画面の 1 割以上の大きさであること。
- 操作先の IME がオフになること: Windows 10 バージョン 2004（ビルド 19041.388）以降または Windows 11 で、キーボード配列が日本語なら、IME オフキーで自動的にオフになります。古い Windows では、MS-IME で 無変換 に IME オフを割り当てて「無変換（IME オフに割り当て済みの場合）」を選ぶか、IME を手でオフにしてから始めてください。
- 「ブラウザー経由で開くウィンドウ」を使うブラウザーに合わせること。**Firefox では必ず「Firefox のプライベート（Ctrl+Shift+P）」を選んでください**（ブラウザー経由になるときは、設定の選択欄の下にも案内が出ます）。Firefox の Ctrl+Shift+N は「最近閉じたウィンドウを開き直す」キーです。既定の「Chrome / Edge のシークレット（Ctrl+Shift+N）」のままだと、閉じたウィンドウがあればそれが開き直され、そのタブが確認ページとテキストのページに置き換わってから閉じられ、「一時ウィンドウを閉じられませんでした」で止まります（Ctrl+V は送りません。開き直したウィンドウにタブが 1 つしかなければ、ウィンドウごと閉じて正しく貼り付けられます）。閉じたウィンドウがなければ「新しいウィンドウを確認できませんでした」で止まります。シークレット / プライベートが管理者に無効にされている場合は「通常の新しいウィンドウ（Ctrl+N）」を選びます（履歴に残ります）。

**ブラウザー経由の副作用**

- 操作先の画面で、一時的なシークレット（プライベート）ウィンドウが開き、確認ページ（赤 → マゼンタ）とテキストのページ（緑 → 青）を表示してすぐ閉じます。確認ページは毎回開きます。
- 操作先のクリップボードがこのテキストで上書きされます。Windows のクリップボードの履歴（Win+V）がオンなら、履歴にも残ります。
- 操作先の IME はオフのまま残ります（元に戻しません）。Mac の かな キー（LANG1 = IME オン）などで戻してください。
- 「通常の新しいウィンドウ（Ctrl+N）」では、テキストを含む URL がブラウザーの履歴に残ります（Chrome / Edge は打ち込んだ data: URL を履歴に保存します）。シークレット / プライベートなら残りません。
- Chrome は http / https / ftp 以外の入力を検索候補のサーバーに送りません。シークレットでは検索候補そのものが無効です。
- 初回だけ確認「ブラウザー経由で入力します」（所要時間つき）が出ます。OK を押すと `nanokvm-usb-paste-bridge-intro` に記録し、このブラウザーでは以後出ません。キャンセルすると何も送りません。

**Ctrl+Shift+U（Linux）の条件と注意**

- IBus 1.5.19 以降、fcitx5 5.0.20 以降、GTK アプリ（GTK 自身の入力処理）、Chromium 系ブラウザー（ブラウザー自身の入力処理）で使えます。
- 1 コードポイントずつ、Ctrl+Shift+U、16 進数（4 桁以上。上段の数字キーと a〜f のキー）、Space の順に送ります。確定は Space です（Enter だとフォームを送信するおそれがあるため）。例: あ = Ctrl+Shift+U 3 0 4 2 Space、𠮷（U+20BB7）= Ctrl+Shift+U 2 0 b b 7 Space。濁点の結合文字や絵文字の組み合わせは、コードポイントごとに分けて送ります。
- 最初の Ctrl+Shift+U のあとは 0.4 秒（IBus がデータを読み込むため）、それ以降は Ctrl+Shift+U のあとと Space のあとに 0.08 秒ずつ待ちます。
- Mozc がひらがなモードだと、数字が Mozc に取られます。直接入力にしてから始めてください（Linux には IME オフキーを自動では送りません）。
- Caps Lock がオンだと、GTK と Chromium は Ctrl+Shift+U を受け付けません（自動オフが効けば問題ありません）。
- 入力メソッドのない端末には Ctrl+U として届きます（bash などでは行の削除）。端末には使わないでください。
- 行・ピル・ホットキーからのキャンセルと、Mac でのキー入力（実行中は操作先に届きません）では、入力中の 1 文字を Space まで送ってから止まります（操作先を入力途中のまま残さないため）。それが最後の 1 文字なら、全部入力し終えたので「完了」になります。クリック（操作先にも届くため）、タブの非表示（バックグラウンドのタブではタイマーが約 1 秒単位に間引かれ、キーが押されたままになって操作先でオートリピートするため）、シリアルエラーでは、文字の途中でもすぐ止まります。操作先に入力途中のコード（下線付きの `u30` など）が残ったら、操作先で Escape を押して取り消してください。

**進捗と停止**

- 進捗ピル（画面下中央）は、所要時間が 0.7 秒を超える・入力できない文字がある・途中で止まった、のいずれかで表示されます。正常完了の 3 秒後に消えます。仮想キーボードを開いている間はメニューバーの下に移動します。ブラウザー経由の間は、今の段階と「完了まで操作しないでください」も出ます。
- 入力できない文字は打たずに、件数と文字（最大 50 種、見えない文字は U+XXXX）を表示します。対象は、直接入力で打てない文字（「入力しない（ASCII のみ）」のときと、操作先が macOS のとき）と、タブと改行以外の制御文字です。
- 停止条件: ホストで修飾キー以外のキーを押す（オートリピートは除く）、ページをクリック（貼り付けの UI 内は除く）、タブが非表示、シリアルエラー、行・ピル・ホットキーからのキャンセル、ブラウザー経由の確認の失敗（映像、画面の静止、ウィンドウ、確認ページ、内容、コピー、閉じたこと）、Caps Lock をオフにできない。実行中は物理キーボードはミュート、仮想キーボードは無視、ショートカット行は無効表示になります。
- 実行中は、マウスの移動とホイール（2 本指スクロールとその慣性を含む）を操作先に送りません（絶対座標・相対座標・タッチとも）。ブラウザー経由が画面の変化を見ている間に、操作先の画面を動かさないためです。ボタンの押下と解放は送ります（押下は上のとおり貼り付けを止めます）。
- 2,000 文字を超えると所要時間つきの確認ダイアログ、20,000 文字で切り詰め（通知あり）。
- ブラウザー経由が途中で止まると、一時ウィンドウが残ることがあります。操作先で閉じてください（マウスで × を押すなど）。
- IME オフキーが効かない環境（古い Windows、Linux）で操作先の IME がオンだと、入力が化けます。Caps Lock の状態を読めないときにオンだと、英字の大小が反転します（ブラウザー経由では、確認ページが赤のままになって止まります）。

### 音声入力バー（Mac の音声入力・日本語入力を操作先へ）

キーボードメニュー →「音声入力バー」で、画面下に入力欄を出します（もう一度押すか × で閉じる）。欄にカーソルがある間、Mac のキーボードは操作先に送られず、欄に入ります。

- 欄をクリックして Mac の音声入力（マイクキー）で話す、または Mac の日本語入力で打つ。
- **Enter** で送信。「止まったら自動で送信」がオンなら、入力が 1.5 秒止まった時点で自動送信します（変換中は送りません）。
- 送った文は「クリップボードを入力」と同じ設定（速度・改行・日本語の入れ方）で操作先に打ち込まれます。入力中に次の文を送ると順番待ちになり、前の文が終わってから続きます。途中で止まったときは、未送信の文が欄に戻ります。
- **Esc** か映像のクリックで、キーボードが操作先に戻ります。

日本語をウィンドウを開かずに入れるには、「クリップボードを入力」の設定 →「日本語など（ASCII 以外）」を **IME コード入力** にするのがおすすめです。操作先の準備は要りません（次の節。最初はメモ帳で試してください）。IME コード入力の条件を満たせない操作先では、レジストリの設定が必要な **Alt＋テンキー** も選べます（その次の節）。既定の「自動」のままだと、Windows の操作先ではブラウザー経由になり、文を送るたびに一時ウィンドウが開きます。

### IME コード入力（Windows）

「クリップボードを入力」の設定 →「日本語など（ASCII 以外）」で「IME コード入力（Windows・ウィンドウを開かない）」を選ぶと使えます。操作先の Microsoft IME（日本語）が持つコード入力（文字コードを打って F5 で変換する機能）で、キーで打てない文字を 1 文字ずつ入力します。選択中の入力欄にそのまま入り、ウィンドウは開かず、操作先のクリップボードも使いません。操作先の設定を変える必要もありません。「クリップボードを入力」でも音声入力バーでも同じように働きます。日本語の Microsoft IME が操作先で有効になっている必要があるので、「自動」がこの方法を選ぶことはありません。

**打ち方**

1. 最初に IME オフキー（LANG2 = 0x91）を送ります。「入力前に操作先の IME をオフにする」の設定には関係なく、必ず送ります（キーだけで打てるテキストでも送ります）。
2. ASCII と改行は、IME がオフのまま、これまでどおりキー配列のキーで打ちます。
3. キーで打てない文字（日本語、全角の記号、絵文字など）が始まるところで、IME オンキー（LANG1 = 0x90）を送ります。IME がどの状態にあっても、ひらがなモードでオンになります。
4. 1 コードポイントごとに、文字コードの 16 進数（上段の数字キーと a〜f のキー。Shift は使いません）、F5（変換）、Ctrl+M（確定）を送ります。この並びは 1 コードポイント分をひとまとまりとして送ります（キャンセルは、ひとまとまりを送り終えてから効きます）。
5. キーで打てる文字と改行の前、そしてテキストの最後で、IME オフキー（LANG2）を送ります。

例: `aあ😀b` は、LANG2、a、LANG1、3 0 4 2 F5 Ctrl+M、0 1 f 6 0 0 F5 Ctrl+M、LANG2、b の順に送ります。

- 文字コードの桁数は決まっています。U+FFFF までは 0 で埋めた 4 桁（`3042`、`00e9`、`ff01`）で、これより短くても長くても変換されません。U+10000 以上は 0 で埋めた 6 桁（`01f600`、`020bb7`）です。5 桁は使いません。10 進数だけの 5 桁は JIS X 0213 の文字コードとして読まれることがあり、測定では `21516` が別の漢字になりました。
- U+30000〜U+3FFFF の文字は、どちらの桁数でも変換されません。UTF-16 のサロゲート 2 つを、4 桁のコード 2 回（それぞれに F5 と Ctrl+M）に分けて入力します。測定では、これで正しい 1 文字になりました。この 2 回はひとまとまりとして送るので、キャンセルで前半だけが入って止まることはありません。
- 濁点などの結合文字や、複数のコードポイントでできた絵文字（肌の色、ZWJ でつないだもの、U+FE0F 付き、国旗）は、コードポイントごとに 1 回ずつ入力します。
- タブは、Tab キーを押さずに、タブ文字として入力します。IME コード入力で打つテキスト（キーで打てない文字を含むテキスト）の中のタブは、文字コード `0009` を、ほかの文字と同じ手順（F5、Ctrl+M）で入力します。Tab キーを押すとフォーカスが入力欄の外へ移り、次の文字の F5 が、変換する文字のないままアプリに届くためです。測定では、Edge の textarea と contenteditable の欄、CKEditor 5、メモ帳のどれでもタブ文字が入り、フォーカスは動きませんでした。表計算ソフトでセルを移るような、Tab キーとしての働きはしません。キーだけで打てるテキストは直接入力なので、ほかの方法と同じく Tab キーを押します（ブラウザーの入力欄ではフォーカスが次の項目へ移り、残りの文字はそこに打たれます）。
- 確定は Enter ではなく Ctrl+M です。どちらでも確定でき、IME はオンのまま残りますが、IME がオンになっていなかった場合、Enter は 1 文字ごとの改行（チャット欄では送信）になります。Ctrl+M は、変換する文字がないときに送っても、測定した Edge では入力欄の内容もフォーカスも IME の状態も変えませんでした。Edge 自身の Ctrl+M のショートカット（タブのミュート）が働くかどうかは確認していません。変換中の Ctrl+M は、ページにはキーコード 229 のキーイベントとしてしか届きません。測定した Edge の入力欄と CKEditor 5 では、500 回を超える入力のどれでも、Ctrl+M のキー押下、送信になる Enter、変換する文字のない F5 がページに届くことはありませんでした。Microsoft Teams には Ctrl+M のショートカット（メッセージの一覧にフォーカスを移す）があります。2026 年 11 月に読んだ Teams の Web クライアントのコードでは、ショートカットをキー押下のキーコードで判定しているので、既定のショートカットのままなら、変換中の Ctrl+M にも Enter にも反応しません。ユーザーが割り当て直したショートカットは別の方法で判定されるので、Ctrl+M に割り当ててあると働きます。これはコードを読んだ結果で、Teams で測定したものではありません。IME がオンになっていなかった場合は、Ctrl+M のたびにフォーカスが Teams の入力欄の外へ移ります（送信はされません）。
- F5 のあとは必ず Ctrl+M を送ります。変換候補が開いている間に打った数字は、次の文字コードではなく候補の選択になるためです。LANG2 や Shift+Enter、次の文字コードでは確定されません。

**条件**

- 操作先が Windows で、日本語の Microsoft IME が、操作先で今選ばれている入力方式であること。
- IME オンキー（LANG1）と IME オフキー（LANG2）が操作先で効くこと。測定した Windows 11 では、キーボードの配列が日本語（106/109）でも英語（101/102）でも効きました。
- IME がローマ字入力（既定）であること。かな入力にしてあると、文字コードのキーがかなとして入り、すべて違う文字になります。エラーは出ないので、気づかないまま入力が進みます。
- IME が使える入力欄であること。IME がオンにならない場合（日本語の IME が有効でない、IME が無効な欄）は、数字がそのまま文字として入り、F5 と Ctrl+M がアプリに届きます。Edge では、変換する文字がないときの F5 はページの再読み込みになり、入力欄の内容が消えました。
- 速度は「標準」か「安全」で打ちます。IME コード入力で打つテキストは、「高速」を選んでも「標準」の速さ（押下 20 ms / 間隔 20 ms）で打ちます。ASCII と改行も含めたテキスト全体が、「標準」とまったく同じ打ち方になります。キーだけで打てるテキストは、これまでどおり選んだ速度で打ちます。`資料は` が `資５９９は` になるように、1 文字が全角の数字や英字のまま入るときは、操作先の処理がキーに追いついていません。速度を「安全」にしてください。理由は下の「測定結果」にあります。

**測定結果**

開発時に、仮想マシン上の日本語版 Windows 11（26H2、ビルド 26300）で測りました。既定の新しい Microsoft IME、ローマ字入力です。最初の 5 項目は、測定用の送信プログラムで Edge の textarea と contenteditable の欄に入力した結果です。残りは、このアプリが実際に送る打鍵列での結果です。

- 押下 20 ms / 間隔 20 ms（「標準」と同じ）と、すべてのキーを 10 ms / 10 ms で、合わせて約 26,000 文字を入力し、誤りは 0 文字でした。
- 4 桁のコードでは、F5 の第 1 候補が必ず Unicode の文字でした（cp932 の 2 バイト文字すべてを含む 9,384 種類）。候補を選び直しても、次の結果は変わりませんでした。
- LANG1、LANG2、F5、Ctrl+M のあとに待ち時間を入れなくても、この 2 つの欄では、20 ms / 20 ms と 10 ms / 10 ms で誤りが出ませんでした。
- この 2 つの欄では、5 ms / 5 ms 以下でだけ起きる失敗が 1 種類ありました。contenteditable の欄で、改行のすぐあとに日本語が続くと、最初の確定の直後の数字が 1 つ抜けることがあります（400 区間のうち 9 区間。その文字は、残りの 3 つのキーがそのまま入ります）。区間の最初の F5 のあとに 0.1 秒待つと、240 区間で 0 になりました（その前の別の測定では、同じ 5 ms / 5 ms で、この待ちを入れても 1,100 文字のうち 2 文字が誤りました）。このアプリは 10 ms / 10 ms より速くは打ちませんが、余裕としてこの 0.1 秒を毎回入れています。
- 以前のバージョンの Microsoft IME（IME の設定の「互換性」）でも、20 ms / 20 ms と 10 ms / 10 ms では同じ結果でした。5 ms / 5 ms 以下では F5 が無視されました。
- このアプリが送る打鍵列を、Edge の 2 つの欄と、リッチテキストエディターの CKEditor 5（39.0.0、47.6.2、49.1.0。Teams のメッセージ入力欄もこの CKEditor 5 で作られています）に入れました。20 ms / 20 ms では、違う文字が入ることはありませんでした（チャットの文 15 種類とそのほかの文 15 種類を、5 つの入力先それぞれで。フォーカスが移った直後の入力は 58 回のうち 58 回）。
- すべてのキーを 10 ms / 10 ms で打つと、入力欄にフォーカスが移った直後（ページを開いた直後や、欄をクリックした直後）の最初の入力で、3 文字目の最初の数字が抜けることがありました（200 回のうち 20 回。Edge の 2 つの欄では 75 回のうち 0 回）。フォーカスが移ったあとの 2 回目の変換だけ、IME が 23〜30 ms かかるためです（ふだんは約 5 ms）。F5 と Ctrl+M のあとを 40 ms にすると、これは起きなくなりました（196 回のうち 196 回）。
- それでも、入力イベント 1 回の処理に 30 ms かかるページでは、20 ms おきに届く数字に処理が追いつかず、84 回のうち 10 回で数字が 1 つ抜けました。キーの間隔をすべて 40 ms にしても、キーを押している時間が 10 ms のままだと、この遅いページを開いた直後の最初の入力で、20 回のうち 2 回、数字が抜けました。20 ms / 20 ms では、この遅いページでも抜けませんでした（104 回のうち 104 回。そのうち 20 回は、ページを開いた直後の最初の入力）。このため、IME コード入力で打つテキストは、「高速」を選んでも「標準」とまったく同じ打ち方にしています。
- 間隔で決まるのは、操作先の処理がどこまで遅くても追いつけるかです。入力イベント 1 回に 45 ms 以上かかるページでは、20 ms / 20 ms でも数字が抜けました（46 回のうち 5 回）。同じページで「安全」にすると、30 回のうち 30 回正しく入りました。
- メモ帳でも、通常の文と、1 つのコードポイントでできた絵文字は正しく入りました。国旗、家族、肌の色付きのような、複数のコードポイントでできた絵文字は、メモ帳自身の処理で崩れます（測定用の送信プログラムでも同じ結果でした）。その次の文字の F5 がメモ帳に届いて、日時が挿入されることもありました。

所要時間は、1 文字あたり 6 打鍵（4 桁、F5、Ctrl+M）で、標準でも高速でも約 0.24 秒（1 打鍵 0.04 秒）、安全で約 0.6 秒です。U+10000 以上の文字は 8 打鍵です。日本語の区間ごとに、LANG1、LANG2、0.1 秒が加わります。

**制限と注意**

- 測定していないもの: Microsoft Teams のデスクトップアプリ、Windows 10、実機の USB キーボードの経路（NanoKVM-USB 経由）。これらで動くかどうかは、まだ分かっていません。[TESTING.ja.md](TESTING.ja.md) の 6-22〜6-28 が、その確認の手順です。
- かな入力の IME では、エラーなしですべて違う文字になります。IME がオンにならない欄では、数字がそのまま入り、F5 と Ctrl+M がアプリに届きます（どちらも上の「条件」）。
- 確定した文字は、1 文字ずつ操作先の IME の入力履歴に入り、予測候補に出てくるようになります。
- 途中で止めると、操作先の IME がオンのまま残ることがあります（最後の IME オフキーを送る前に止まるため）。Mac の 英数 キー（LANG2）などでオフに戻してください。行・ピル・ホットキーからのキャンセルと、Mac でのキー入力では、入力中の 1 文字を Ctrl+M まで送ってから止まります。それが最後の 1 文字なら、残っているのは IME オフキーだけなので、それも送って「完了」になります。このとき音声入力バーは、順番待ちの文を送らずに入力欄へ戻します（止める操作をしたためです）。
- クリック、タブの非表示、シリアルエラーでは、文字の途中でもすぐ止まります。このときは、何も残っていないように見えても、やり直す前に操作先で Esc を 2〜3 回押してください。確定前の文字（下線付きの数字や変換候補）が画面に見えなくても IME の中にだけ残っていて、次に打ったキーと一緒に戻ってくることがあります。測定では、Esc を押さずに次の入力をすると、打ちかけの数字が欄に残り、次の日本語の最初の 1 文字が文字コードのまま入りました（`お疲了解しました` になるはずが `お疲３０４え８６解しました`）。Esc を 1 回押してからなら、そのあとの入力は正しく入りました。
- 最後まで入力したあとは、操作先の IME はオフになっています（元の状態には戻しません）。

**最初の試し方**

1. 操作先でメモ帳を開き、文字を打てる状態にします。IME はオンでもオフでも構いません。
2. 「日本語など（ASCII 以外）」を「IME コード入力」にして、`aあ😀b` のような短い文を入力します（設定のテキスト欄か、音声入力バーから）。
3. `aあ😀b` と入れば成功です。`3042` のような数字がそのまま入るときは、IME がオンになっていません（日本語の Microsoft IME が有効か確かめてください）。かなが入るときは、IME がかな入力になっています。
4. メモ帳でうまくいったら、実際の入力先（Teams など）の、消えても困らない欄で同じ文を試します。

メモ帳から始めるのは、うまくいかなかった場合に F5 や Ctrl+M がアプリに届いても、チャットの送信やページの再読み込みのような取り消せないことが起きないようにするためです。測定では、変換する文字のない F5 がメモ帳に届くと日時が挿入され（IME がオンになっていない目印になります）、Ctrl+M では何も起きませんでした。

Enter で送信されるチャットアプリ（Teams など）に入れるときは、「改行」を Shift+Enter にしてください。Enter のままだと、テキストの中の改行のたびにメッセージが送信されます。

### Alt＋テンキー（Windows）

「日本語など（ASCII 以外）」で「Alt＋テンキー（Windows・ウィンドウを開かない・要設定）」を選ぶと使えます。IME コード入力の条件を満たせないときの、ウィンドウを開かないもう 1 つの方法です。操作先の Windows で一度だけ準備が必要です。

1. `Win+R` → `regedit` → `HKEY_CURRENT_USER\Control Panel\Input Method` を開く。
2. 文字列値 `EnableHexNumpad` を作り、値を `1` にする。
3. サインインし直す。

この方式は 1 文字ごとに「Alt を押したままテンキーの＋ → 文字コード（16 進）」を打ちます（速度「高速」で 1 秒に 10 文字ほど）。準備をしないまま使うと Alt＋英字が操作先のメニュー操作として働くので、必ず先に設定してください。**操作先の NumLock はオンにしておいてください。** 測定では、既定の（新しい）Microsoft IME で NumLock がオフだと、何も入力されませんでした（以前のバージョンの Microsoft IME では、NumLock に関係なく入力できました）。アプリによっては効かないことがあります（実機未検証）。

## 副作用

- ⌘ キー変換がオンで振り分けがオフのとき、⌘ を押しながらのクリックは操作先では Ctrl+クリック、⌘＋ホイールは Ctrl+ホイール（ズーム）になります。⌃クリックは右クリックにはなりません。
- 同じ条件でシリアル接続中は、タブを閉じる・再読み込み・戻るで「このサイトを離れますか？」の確認が出ます。
- 右 ⌘ も Ctrl になるため、Win キー単体はショートカットの「Win」行から送ります。
- 英数/かな の変換をオンにすると、押したキーはホスト側の IME も切り替えます（ホストと操作先が揃うので実害はありません）。
- 貼り付けでは、Windows の操作先にテキストより先に IME オフキー（LANG2）を送るので、操作先の IME はオフになります（元に戻しません）。
- 操作先の Caps Lock がオンなら、貼り付けの前にオフにします（元に戻しません）。
- 貼り付けの実行中は、マウスの移動とホイールが操作先に届きません（ボタンは届きます）。
- ブラウザー経由では、操作先で一時ウィンドウが開いて閉じ、操作先のクリップボードが上書きされます（「[クリップボードを入力（貼り付け）](#クリップボードを入力貼り付け)」の「ブラウザー経由の副作用」）。
- IME コード入力では、確定した文字が操作先の IME の入力履歴に残り、予測候補に出てくるようになります。途中で止めると、操作先の IME がオンのまま残ることがあります（「[IME コード入力（Windows）](#ime-コード入力windows)」の「制限と注意」）。

## 既知の制限

- ⌘Tab、⌘Space、⌘Q、⌘⌥Esc、スクリーンショット系は macOS が先に処理するため送れません（ショートカットメニューを使ってください）。⌘W/T/N/⇧[ ] などは全画面＋キーボードロック時のみ届きます。
- 日本語など（ASCII 以外）は、Windows ではブラウザー経由、Linux では Ctrl+Shift+U で入力します。操作先 OS が macOS のときは入力せず、「入力できない文字」として報告します（どちらの方法も Ctrl のショートカットを使うため。⌘ を使う macOS 向けの方法は未実装）。US / JIS は操作先の設定に合わせる必要があります。
- IME コード入力を測定したのは、仮想マシン上の Windows 11 の、Edge の入力欄、CKEditor 5、メモ帳だけです。Microsoft Teams のデスクトップアプリ、Windows 10、実機の USB キーボードの経路では測定していません。IME がかな入力だとすべて違う文字になり、IME がオンにならない欄では数字と F5、Ctrl+M がそのままアプリに届きます（「[IME コード入力（Windows）](#ime-コード入力windows)」）。
- 10 進数の Alt コード（Alt を押したままテンキーで 10 進数を打つ方法）は使いません。既定の（新しい）Microsoft IME では値の下位 1 バイトしか使われず（測定では、Alt+33440 が「あ」ではなく「á」になりました）、RichEdit 系のアプリは値を CP932 ではなく Unicode として読むためです。16 進数で打つ「Alt＋テンキー」は選べますが、操作先のレジストリの設定が必要で、NumLock がオフだと既定の Microsoft IME では何も入力されません。
- ブラウザー経由はテキスト全体を 1 つの URL で送ります（分割しません）。長いほど時間がかかり（日本語 2,000 文字で標準約 5 分 45 秒）、途中で止まると最初からやり直しです。
- ブラウザー経由で直接貼り付けられるのは、ブラウザーの中の欄だけです。映像が必要で、HDMI に映らない画面では使えません。操作先の画面が動き続けている間（動画の再生中など）は始められません。Windows では ASCII 以外が 1 文字でもあるとテキスト全体がこの経路になるので、ほかのアプリには「入力しない（ASCII のみ）」で入れるか、ブラウザーの欄から移してください。
- ブラウザー経由のコピーの確認（青）は、ページが Ctrl+C を受け取ったことの確認です。そのあとの OS のクリップボードへの書き込みの失敗（ほかのアプリがクリップボードを使用中、情報漏えい対策ソフトがブラウザーからのコピーを止めたなど）は検出できず、そのときは Ctrl+V で前のクリップボードの内容が貼り付けられます。
- 自動でオフにした Caps Lock は元に戻しません。IME オフキーでオフにした IME も戻しません。
- Caps Lock の補正は「macOS がロックオンで keydown、オフで keyup を出す」前提です。操作先と 2 回ずれるような挙動なら、チェックを外してください。macOS の「Caps Lock で入力ソースを切り替える」設定とは相性がよくありません。
- 「英数/かな → 無変換/変換」は MS-IME に IME オフ/オン を割り当てている場合にだけ意味があります（既定ではオフ）。Windows 10 2004 以降 / 11 の日本語キーボードなら、オフのままで 英数/かな が IME オフ/オン として働きます。
- 機器（CH9329）から読むのは、貼り付けの前の Caps Lock の状態だけです。ホストと操作先の Caps Lock / NumLock の同期（LED 同期）や、キーごとに応答（ACK）を待って送る制御はしていません。
- 相対座標モードはポインターロック（Chrome）が前提で、Esc で解除されます。
- HID ログに出るのは、送信したキーボードとマウスのレポートだけです（機器の応答と、Caps Lock の状態を読む GET_INFO は出ません）。

## upstream からの挙動変更

設定を何も触らないユーザーにも影響する変更です（spec §8 ＋ このフォーク独自の既定値）。

- **Mac ホストでは ⌘ が既定で Ctrl として送られます**（upstream: ⌘ = Win）。キーボード → ⌘ キー変換 → オフ で upstream と同じキーボードのバイト列になります。操作先 OS を macOS にしても無効になります。有効かつシリアル接続中はタブを閉じるときに確認が出ます。
- スクロールが 1 イベント 1 ノッチではなく移動量に比例するようになりました（px 積算＋最初のノッチの即発火）。
- 絶対座標モードは Pointer Events とポインターキャプチャを使うため、動画の外で離してもボタンが押しっぱなしになりません。フォーカス喪失・タブ非表示でもボタンを離します。
- 右端・下端の座標が 4095 になります（upstream は 4096 を送っていました）。
- 相対座標モード: 小さい移動量を 2 倍にするルールを廃止（代わりにポインター速度スライダー）、ロック中以外は何も送らない（ロック取得のクリックが操作先に届かない）、大きな移動は分割して全距離を送る、ロック解除でボタンを離す。
- マウスの移動レポートはシリアル書き込み中に間引かれます（絶対座標は最新を優先、相対座標は合算）。ボタン・ホイール・解除は捨てません。キーボードは対象外です。
- マウスジグラーが実際に動くようになりました（相対マウスのコマンドで送信）。
- 貼り付けは 20 ms / 20 ms のペースで、進捗・キャンセル・強制停止つきになりました（upstream は 50 ms 押下のみで止められませんでした）。JIS の変換表は「操作先のキー配列」が JIS のときだけ使われます。キー配列で打てない文字（日本語など）は、Windows ではブラウザー経由、Linux では Ctrl+Shift+U で入力します。macOS では黙って捨てずに報告します。
- 貼り付けでは、Windows の操作先にテキストより先に IME オフキー（LANG2）を送ります。操作先の Caps Lock がオンなら、先にオフにします。
- 貼り付けの実行中は、マウスの移動とホイールのレポートを送りません（絶対座標・相対座標・タッチとも）。ボタンの押下と解放は送ります。
- シリアルの受信を常に読み取るようになりました（upstream は機器の応答を読まずに溜めていました）。受信エラー（ブレーク、フレーミング、パリティ、オーバーラン）のあとも、ポートが新しい受信ストリームを出せば読み続けます。貼り付けの前には（「操作先の Caps Lock がオンなら自動でオフにする」がオンなら）、Caps Lock の状態を読む GET_INFO（`57 AB 00 01 00 03`）を機器に送ります。機器への問い合わせなので、操作先には何も届きません。
- 日本語のブラウザーでは UI が日本語になります。

それ以外のレポートは upstream とバイト単位で同一です（パリティテストで検証）。

### HID ログ（`?debug=hid`）

`http://localhost:3001/?debug=hid` で開くか、キーテスト（キーボード → ⌘ キー変換 → 送信できるショートカット）右下の「HID ログ」をクリックすると、左下に送信レポートのパネルが出ます。

```
 +Δt  種別  バイト列                  デコード
  +0  kb    01 00 00 00 00 00 00 00  Ctrl
 +12  kb    01 00 06 00 00 00 00 00  Ctrl + C
 +50  kb    01 00 00 00 00 00 00 00  Ctrl
+180  kb    00 00 00 00 00 00 00 00  (none)
  +8  abs   02 00 ff 0f 00 08 ff     x=4095 y=2048 btn=- whl=-1
  +9  rel   01 01 7f 00 00           dx=127 dy=0 btn=L whl=0
```

- `kb` = 8 バイトのキーボードレポート、`abs` = 絶対座標のペイロード（x/y は 0〜4095）、`rel` = 相対座標のペイロード（符号つき int8）。`+Δt` は直前のレポート（種別を問わず）からの ms。
- 表示は最新 12 件、バッファーは 200 件。「コピー」で全件をテキストでコピー、「クリア」で消去。書き込みに失敗したレポートは赤で表示されます。
- × を押すと閉じて `nanokvm-usb-debug-hid` を解除します。URL に `?debug=hid` が付いていれば次回も表示されます。
- 記録はパネルが閉じていても常に行われているので、開いた直後から直前の履歴を見られます。
