# NanoKVM-USB ブラウザー版 — kawa フォーク ガイド

Mac（MacBook のトラックパッド、日本語環境、Chrome）から NanoKVM-USB 経由で Windows 機を操作するための個人フォークです。upstream（[sipeed/NanoKVM-USB](https://github.com/sipeed/NanoKVM-USB) の `browser/`）に次の 3 つを足しています。設定を何も触らなくても変わる点は「[upstream からの挙動変更](#upstream-からの挙動変更)」にまとめました。それ以外の HID レポートは upstream とバイト単位で同一です。

公開ページ: **https://yka57.github.io/kawa-kvm/**（「[Mac で動かす](#mac-で動かす)」参照）

| 機能                                                                                                                                                                                       | 場所                                                          | 既定値                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- | ----------------------------------------------------------- |
| **⌘ キー変換** — ⌘ を Ctrl として送信（⌘C/⌘V/⌘F が Ctrl+C/V/F になる）＋ Mac 風ナビゲーション                                                                                              | キーボード → ⌘ キー変換（Mac）                                | **オン**（Mac ホストかつ操作先 OS が macOS 以外のとき有効） |
| **トラックパッド / スクロール** — 2 本指スクロールを移動量に比例させる、ボタンが押しっぱなしにならない絶対座標、相対座標のポインター速度                                                   | マウス → ホイール速度 / ポインター速度                        | スクロール感度 100 px/ノッチ、ポインター速度 ×1.00          |
| **クリップボードを入力** — Mac のクリップボードを操作先にキー入力として打ち込む（US / JIS 配列対応、日本語は Windows ではブラウザー経由・Linux では Ctrl+Shift+U、進捗表示、いつでも中断） | キーボード → クリップボードを入力（⚙ = 設定）、ホットキー ⌘⇧V | 速度「標準」、改行 = Enter、日本語など = 自動、⌘⇧V 有効     |

あわせて、共通設定の「操作先 OS」「操作先のキー配列」、日本語 UI（日本語のブラウザーでは自動選択）、「全キーを離す」、HID ログ（`?debug=hid`）を追加しています。

## Mac で動かす

**一番簡単なのは公開ページを開くことです。** `main` に push するたびに GitHub Actions（`.github/workflows/pages.yml`。`npm run build:pages` = `build` に `--base=/kawa-kvm/` を付けたもの）がビルドして次の URL に公開します。

**https://yka57.github.io/kawa-kvm/**

NanoKVM-USB を Mac に挿し、Chrome でこの URL を開いてカメラとシリアルポートを許可するだけです。Mac には何もインストールしません。ページは Chrome の中で動き、Mac の USB 経由で直接デバイスと通信します。サーバーは静的ファイルを渡すだけです（`https://` はセキュアコンテキストなので WebSerial が使えます）。新しい版を反映するにはページをリロードします。

**ローカルで動かす場合:** WebSerial とカメラは **セキュアコンテキスト**（`https://` または `localhost`）でしか使えません。NanoKVM-USB を挿した Mac 上で開発サーバーを起動し、`localhost` で開きます。

```shell
git clone https://github.com/yka57/kawa-kvm.git   # または rsync でフォルダーを Mac にコピー
cd kawa-kvm
npm install
npm run dev                 # Vite が http://localhost:3001 で起動
```

Chrome で **http://localhost:3001** を開きます（WebSerial は Chromium 系のデスクトップブラウザーのみ）。`http://localhost` はセキュア扱いなので、シリアルとカメラの許可ダイアログが出ます。

**LAN の `http://` オリジンはセキュアコンテキストではありません。** 別のマシンから `http://192.168.x.x:3001` で開くと「シリアル非対応」になり、カメラも使えません。別マシンから使う場合は **HTTPS** で配信するか、デバイスを挿したマシン上で **localhost** を使ってください。`npm run build && npm run preview` を使うと本番ビルドを http://localhost:4173 で確認できます。

必要なもの: Node 22（Vite 7 は 20.19 / 22.12 以上）、npm。

## 機能と設定

### 共通設定（キーボードメニュー）

| 行               | 選択肢                   | 既定値                             | 使われる場所                                                                                                                                           |
| ---------------- | ------------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 操作先 OS        | Windows / Linux / macOS  | Windows                            | macOS を選ぶと ⌘ キー変換が無効になります（⌘ はそのまま ⌘ として届きます）。貼り付けの「自動」（日本語などの入力方法、IME オフキー）もこれで決まります |
| 操作先のキー配列 | US (ANSI) / 日本語 (JIS) | UI が日本語なら JIS、それ以外は US | クリップボード入力の記号の変換表、Caps Lock を自動でオフにするキー（JIS は Shift+CapsLock）                                                            |

### ⌘ キー変換（Mac）

Mac ホストでのみ表示されます。有効になる条件は「ホストが macOS **かつ** オン **かつ** 操作先 OS が macOS 以外」です。upstream では ⌘ は Win キーとして送られるため、⌘C は Win+C、⌘ を単押しするとスタートメニューが開いていました。

**オン時の動作**

- 左右の ⌘ → 左右の Ctrl。⌃ は Ctrl のまま、⌥ は Alt のまま。⌘ の単押しは Ctrl の単押しになります（無害）。
- ⌘ を押している間に押したキーは **短いタップ**（押下 → 50 ms 後に自動で離す）として送られます。macOS の Chrome は ⌘ 押下中の keyup を届けないため、押しっぱなし（Ctrl+V の連打）を防ぐ仕組みです。キーを押し続けるとホストのオートリピートで再タップされるので、⌘V を 2 秒押せば貼り付けが繰り返され、離すと止まります。⌘C を素早く押して離しても送られます（最短 30 ms）。
- ⌘⇧V は（ホットキーが有効なら）操作先に送らず「クリップボードを入力」を起動します。

**チェックボックス**

| 項目                       | 既定 | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Mac 風ナビゲーションも変換 | オン | ⌘←/→ → Home/End、⌘↑/↓ → Ctrl+Home/End（Shift はそのまま: ⌘⇧← で行頭まで選択）。⌥←/→ → Ctrl+←/→（単語移動。変換しないと Alt+← = ブラウザーの「戻る」）、⌥⌫/⌥⌦ → Ctrl+⌫/⌦。⌘⇧[ / ⌘⇧] と ⌘⌥←/→ → Ctrl+Shift+Tab / Ctrl+Tab（タブ切り替え。全画面時のみ届きます）                                                                                                                                                                                    |
| 英数/かな → 無変換/変換    | オフ | オフのときは、JIS Mac の 英数 / かな が LANG2 / LANG1 のまま届き、Windows 10 2004 以降 / 11 の日本語キーボードでは IME オフ / オン になります（Mac と同じ使い方）。オンにすると 英数 を 無変換、かな を 変換 として送信します。操作先の MS-IME で「無変換 = IME オフ、変換 = IME オン」を割り当てている場合だけ正しく動きます（既定のキーテンプレートでは無変換はかなモードの切り替えです）。1 回試してから決めてください（TESTING.ja.md の Q1） |
| Caps Lock の同期を補正     | オン | macOS はロックオン時に keydown、オフ時に keyup を出すので、両方で Caps Lock を 1 回タップして操作先と同期させます。オフにすると upstream と同じ（オン時しか届かず、ずれる）                                                                                                                                                                                                                                                                      |

UI のない項目（`nanokvm-usb-keyboard-remap` の JSON を直接編集）: `tapReleaseMs` 50（20〜200）、`minPressMs` 30（0〜100）、`repeatUnderMeta` true。

**送信できるショートカット**（ヘルプ「送信できるショートカット」に同じ一覧があります）

- 通常ウィンドウで届く: ⌘C/V/X/A/Z/⇧Z/F/S/R/P/L/D/1…9/+/−/0、⌘←/→/↑/↓、⌥←/→、⌥⌫
- **全画面＋キーボードロック時のみ**（ヘルプの「全画面にする」ボタン、またはメニューの全画面）: ⌘W/⇧W/T/⇧T/N/⇧N、⌘⇧[ / ⌘⇧]、⌘⌥←/→、⌃Tab
- 届かない（OS が先に取る）: ⌘Tab、⌘Space、⌘Q、⌘⌥Esc、⌘⇧3/4/5 → 「ショートカット」から送ってください。既定の行: Win+Tab、Ctrl+Alt+Del、Alt+Tab、Ctrl+Shift+Esc、Win

**キーテスト**（ヘルプの下部）: 開いている間はキーが操作先に送られません（ドライラン）。最新 6 件の `種別 · code · key · repeat · ⌘⌃⌥⇧ → 送信した HID コード + レポート hex` と「⌘ 押下中に届いた keyup」の回数が出ます。右下の「HID ログ」リンクで HID ログを開けます。

**関連する動作**

- ショートカットの記録モーダルに「⌘ を Ctrl として記録」が出ます（変換が有効なときに表示・既定でオン）。⌘⇧T を記録すると Ctrl+Shift+T として保存されます。
- 「全キーを離す」行: キーボードの全キーとマウスの全ボタンを離すレポートを送ります（何かが押しっぱなしになったとき用）。
- 変換が有効でシリアル接続中は、タブを閉じる・再読み込みすると確認ダイアログが出ます（⌘W/⌘Q は Chrome が先に処理するため、うっかり閉じないように）。
- 変換は物理キーボードの経路だけに効きます。仮想キーボードとショートカットは記録されたコードをそのまま送ります（Win は Win のまま）。

### トラックパッド / スクロール

**絶対座標モード（既定）**

- マウス / ペンは Pointer Events とポインターキャプチャで処理します。動画の外でボタンを離してもボタンアップが送られ、ウィンドウが非アクティブ・タブが非表示になったときも全ボタンを離します。
- 座標は表示の余白（レターボックス）と回転（90/180/270°）を考慮して 0〜4095 に変換します。右端・下端は 4095 です。
- タッチ操作は upstream のままです。

**スクロール（両モード共通）**

- ホイールイベントの px を積算し、`スクロール感度` の px ごとに 1 ノッチ送ります（既定 100 px。スライダー 0 ↔ 400 px、60 ↔ 100 px、100 ↔ 40 px）。
- ジェスチャーの最初のノッチは 3 px で発火（短いナッジで必ず 1 ノッチ）、2 px 以上の逆方向で即座に逆ノッチ、200 ms 以上の間隔で新しいジェスチャー扱い。横方向が主の 2 本指操作は送りません。
- 「ホイール速度」（upstream のスライダー）はノッチ間の最短間隔です（既定 = 最速 = 制限なし）。間隔内のノッチは捨てられます（upstream と同じ意味）。
- 1 レポートあたりのノッチは ±127 に制限します。

**相対座標モード**

- 動画をクリックするとポインターロックを要求します。このクリックは操作先に送られません。ロック中以外は移動・クリック・ホイールを一切送りません。ロックに失敗したら案内が出ます（再クリックで再試行）。
- `ポインター速度`（相対座標モードでのみ表示）: 倍率 0.25〜4（既定 ×1.00、スライダー 50）。端数は持ち越すので、ゆっくり動かしても取りこぼしません。upstream の「小さい移動量を 2 倍にする」ルールは廃止しました。
- 大きく振ると ±127 を超える分を複数レポートに分割して送るので、移動距離がそのまま届きます。Esc などでロックが外れると押しているボタンを離します。

**移動レポートの間引き（coalescing）**

シリアルへの書き込み中に新しい移動が来た場合、絶対座標では最新の位置だけを残し（古い位置は捨てる）、相対座標では移動量を合算して、書き込みが終わった時点で送ります。ボタン・ホイール・全解除のレポートは捨てず、順序も保ちます。キーボードのレポートは対象外です。

**マウスジグラー**: 15 秒操作がないと ±10 px 動かす機能は、upstream ではキーボードのフレームとして送られていて動いていませんでした。相対マウスのフレームで送るよう直しています。

### クリップボードを入力（貼り付け）

**使い方**

1. Mac 側でテキストをコピーする。
2. 操作先で、貼り付け先の欄をクリックしておく（Windows に日本語を送るときは Chrome / Edge / Firefox の中の欄。下の「ブラウザー経由に必要な条件」参照）。
3. キーボードメニュー → 「クリップボードを入力」をクリック（または ⌘ キー変換がオンなら **⌘⇧V**）。
4. 操作先でキー入力として打ち込まれます。実行中は同じ行が「キャンセル」になり、⌘⇧V をもう一度押しても中断します。

クリップボードの読み取りがブロックされている場合は設定モーダルが開き、テキスト欄に貼り付けて「このテキストを入力」で同じ処理ができます（アドレスバーの鍵アイコンから許可することもできます）。ページをクリックしていないと読めない（`noFocus`）、空、シリアル未接続のときはトーストで知らせます。

**入力方法**

テキストを操作先のキー配列（US / JIS）のキーだけで打てるかどうかで決まります。

- 全部打てる（ASCII だけ。「記号を正規化」がオンならスマートクォートなどを ASCII に直してから判定）: これまでどおり 1 文字ずつキーで入力します（直接入力）。
- 打てない文字がある（日本語、全角の記号、`¥`、絵文字など）: 「日本語など（ASCII 以外）」の設定で決まります。既定の「自動」では、操作先 OS ごとに次のとおりです。

| 操作先 OS | 「自動」の方法 | 内容                                                                                                                              |
| --------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Windows   | ブラウザー経由 | テキスト全体（ASCII も含む）を操作先のブラウザーの一時ウィンドウに URL として打ち込み、コピーして元の欄に貼り付けます             |
| Linux     | Ctrl+Shift+U   | キーのある文字はそのまま打ち、それ以外は 1 コードポイントずつ Ctrl+Shift+U、16 進数、Space で入力します                           |
| macOS     | 入力しない     | 打てない文字はスキップして一覧を表示します。どちらの方法も Ctrl のショートカットを使うので、明示的に選んでも macOS には送りません |

ブラウザー経由と Ctrl+Shift+U は、コピーした文字をそのまま届けます。記号の正規化も Unicode の NFC 正規化もしません。行うのは、先頭の BOM の除去、改行（CRLF / CR）の LF への統一、末尾の改行 1 つの削除（設定がオンのとき）、タブと改行以外の制御文字の除外だけです。

**入力前の IME と Caps Lock**（すべての方法で共通）

- IME: 「入力前に操作先の IME をオフにする」が「自動」なら、操作先 OS が Windows のときだけ IME オフキー（HID の LANG2 = 0x91）を 1 回送り、0.15 秒待ってから入力します。Windows 10 2004 以降 / 11 の日本語キーボードでは、Microsoft IME がどの状態からでもオフ（半角英数）になります。何度送っても同じで、古いビルドでは無視されるだけです。Linux と macOS には「自動」では送りません。ブラウザー経由では、開いたウィンドウのアドレスバーで送ります。無変換（0x8B）は既定の Microsoft IME では IME をオフにしない（かなの種類が切り替わる）ので、IME オフを割り当てた場合だけ選んでください。
- Caps Lock: 「操作先の Caps Lock がオンなら自動でオフにする」がオンなら、入力の前に機器（CH9329）から操作先のキーボード LED の状態を読みます。Caps Lock がオンなら、JIS では Shift+CapsLock（JIS では CapsLock 単独は 英数 キーのため）、US では CapsLock を送り、オフになったことを最大 1 秒で確かめます。オフにならなければ「停止: 操作先の Caps Lock をオフにできませんでした」で止まり、テキストは入力しません。状態を読めないとき（機器が応答しない、操作先が USB を認識していない）は何もしません。

**ブラウザー経由のしくみ**

ピルに今の段階と「完了まで操作しないでください」が出ます。

1. 「ウィンドウを開いています」: ビデオから今の画面を記録し、Ctrl+Shift+N（設定により Ctrl+Shift+P / Ctrl+N）で新しいウィンドウを開きます。画面の 1 割以上が変わるまで最大 4 秒待ちます。0.6 秒待ってから Ctrl+L でアドレスバーに移り（Edge の新しいタブページでは、そのままだと入力が検索ボックスに行くため）、IME オフキーを送ります。
2. 「確認ページを開いています」（初回のみ）: `data:text/html,<body bgcolor=magenta>` を打ち込み、マゼンタの画面が出るまで最大 5 秒待ちます。本文を打つ前に、今のキー配列と IME でアドレスバーに正しく打てるかを確かめるためです。成功はこのアプリのページを再読み込みするまで覚えています。キー配列、開くウィンドウ、IME オフキー、操作先 OS のどれかを変えると、もう一度確かめます。
3. 「URL を入力しています」: テキストを入れたページを `data:text/html;charset=utf-8;base64,…` の URL として打ち込み、Delete（自動補完の候補を消す）と Enter を送ります。日本語 1 文字は URL では 4 文字（UTF-8 の 3 バイトの Base64）になります。
4. 「内容を確認しています」: ページはテキストを入力欄に入れてハッシュ値を計算し、一致すれば背景を緑（lime）、違えば赤にします。緑を最大 6 秒待ちます（URL が 2,000 文字を超えると 2,000 文字ごとに 1 秒追加）。赤なら Ctrl+W でそのページを閉じて止まります。
5. 「コピーしています」: Escape（アドレスバーからページの入力欄へ）、Ctrl+A、Ctrl+C を送り、0.25 秒待ちます。
6. 「ウィンドウを閉じています」: Ctrl+W で一時ウィンドウを閉じ、緑が画面から消えるまで最大 3 秒待ちます。OS が元のウィンドウを前面に戻し、ブラウザーが元の欄にフォーカスを戻します。
7. 「貼り付けています」: 0.3 秒待ってから Ctrl+V で元の欄に貼り付けます。

**ブラウザー経由に必要な条件**

- 操作先で、貼り付け先の欄が Chrome / Edge / Firefox の中にあり、フォーカスされていること。ウィンドウを開くキーは前面のアプリに届くので、ブラウザー以外では別の動作になります（メモ帳は新しいウィンドウ、エクスプローラーは新しいフォルダー）。ほかのアプリに入れたいときは、いったんブラウザーの欄に貼り付けてください。テキストは操作先のクリップボードに残るので、目的のアプリで貼り付けられます。
- 映像が表示されていること。画面の変化と色で進み具合を確かめるためです。映像がないと「映像が表示されていないため、ブラウザー経由の入力は使えません」と出て、何も送りません。
- 新しいウィンドウが HDMI の映像に映ること。複数モニターなら取り込んでいる画面で開き、画面の 1 割以上の大きさであること。
- 操作先の IME がオフになること: Windows 10 バージョン 2004（ビルド 19041.388）以降または Windows 11 で、キーボード配列が日本語なら、IME オフキーで自動的にオフになります。古い Windows では、MS-IME で 無変換 に IME オフを割り当てて「無変換（IME オフに割り当て済みの場合）」を選ぶか、IME を手でオフにしてから始めてください。
- 「ブラウザー経由で開くウィンドウ」を使うブラウザーに合わせること。シークレット / プライベートが管理者に無効にされている場合は「通常の新しいウィンドウ（Ctrl+N）」を選びます（履歴に残ります）。

**ブラウザー経由の副作用**

- 操作先の画面で、一時的なシークレット（プライベート）ウィンドウが開いてすぐ閉じます。
- 操作先のクリップボードがこのテキストで上書きされます。Windows のクリップボードの履歴（Win+V）がオンなら、履歴にも残ります。
- 操作先の IME はオフのまま残ります（元に戻しません）。Mac の かな キー（LANG1 = IME オン）などで戻してください。
- 「通常の新しいウィンドウ（Ctrl+N）」では、テキストを含む URL がブラウザーの履歴に残ります（Chrome / Edge は打ち込んだ data: URL を履歴に保存します）。シークレット / プライベートなら残りません。
- Chrome は http / https / ftp 以外の入力を検索候補のサーバーに送りません。シークレットでは検索候補そのものが無効です。
- 初回だけ確認「ブラウザー経由で入力します」（所要時間つき）が出ます。OK を押すと `nanokvm-usb-paste-bridge-intro` に記録し、このブラウザーでは以後出ません。キャンセルすると何も送りません。

**所要時間の目安**（確認ページを開く回は、速度により約 2〜5 秒増えます）

| 内容                            | 安全          | 標準     | 高速          |
| ------------------------------- | ------------- | -------- | ------------- |
| 直接入力、ASCII 300 文字        | 約 30 秒      | 約 12 秒 | 約 6 秒       |
| ブラウザー経由、日本語 1 文字   | 約 29 秒      | 約 14 秒 | 約 9 秒       |
| ブラウザー経由、日本語 300 文字 | 約 2 分 30 秒 | 約 1 分  | 約 33 秒      |
| Ctrl+Shift+U、日本語 300 文字   | 約 3 分 50 秒 | 約 2 分  | 約 1 分 25 秒 |

ブラウザー経由は、ウィンドウの開け閉めなどの固定分に、日本語 1 文字あたり約 0.16 秒（標準）が加わります。

**Ctrl+Shift+U（Linux）の条件と注意**

- IBus 1.5.19 以降、fcitx5 5.0.20 以降、GTK アプリ（GTK 自身の入力処理）、Chromium 系ブラウザー（ブラウザー自身の入力処理）で使えます。
- 1 コードポイントずつ、Ctrl+Shift+U、16 進数（4 桁以上。上段の数字キーと a〜f のキー）、Space の順に送ります。確定は Space です（Enter だとフォームを送信するおそれがあるため）。例: あ = Ctrl+Shift+U 3 0 4 2 Space、𠮷（U+20BB7）= Ctrl+Shift+U 2 0 b b 7 Space。濁点の結合文字や絵文字の組み合わせは、コードポイントごとに分けて送ります。
- 最初の Ctrl+Shift+U のあとは 0.4 秒（IBus がデータを読み込むため）、それ以降は Ctrl+Shift+U のあとと Space のあとに 0.08 秒ずつ待ちます。
- Mozc がひらがなモードだと、数字が Mozc に取られます。直接入力にしてから始めてください（Linux には IME オフキーを自動では送りません）。
- Caps Lock がオンだと、GTK と Chromium は Ctrl+Shift+U を受け付けません（自動オフが効けば問題ありません）。
- 入力メソッドのない端末には Ctrl+U として届きます（bash などでは行の削除）。端末には使わないでください。
- 途中でキャンセルしても、入力中の 1 文字は Space まで送ってから止まります（操作先を入力途中のまま残さないため）。シリアルエラーのときはすぐ止まります。

**進捗と停止**

- 進捗ピル（画面下中央）は、所要時間が 0.7 秒を超える・入力できない文字がある・途中で止まった、のいずれかで表示されます。正常完了の 3 秒後に消えます。仮想キーボードを開いている間はメニューバーの下に移動します。ブラウザー経由の間は、今の段階と「完了まで操作しないでください」も出ます。
- 入力できない文字は打たずに、件数と文字（最大 50 種、見えない文字は U+XXXX）を表示します。対象は、直接入力で打てない文字（「入力しない（ASCII のみ）」のときと、操作先が macOS のとき）と、タブと改行以外の制御文字です。
- 停止条件: ホストで修飾キー以外のキーを押す（オートリピートは除く）、ページをクリック（貼り付けの UI 内は除く）、タブが非表示、シリアルエラー、行・ピル・ホットキーからのキャンセル、ブラウザー経由の確認の失敗、Caps Lock をオフにできない。実行中は物理キーボードはミュート、仮想キーボードは無視、ショートカット行は無効表示になります。
- 2,000 文字を超えると所要時間つきの確認ダイアログ、20,000 文字で切り詰め（通知あり）。
- ブラウザー経由が途中で止まると、一時ウィンドウが残ることがあります。操作先で閉じてください（マウスで × を押すなど）。
- IME オフキーが効かない環境（古い Windows、Linux）で操作先の IME がオンだと、入力が化けます。Caps Lock の状態を読めないときにオンだと、英字の大小が反転します。

## 副作用

- ⌘ キー変換がオンのとき、⌘ を押しながらのクリックは操作先では Ctrl+クリック、⌘＋ホイールは Ctrl+ホイール（ズーム）になります。⌃クリックは右クリックにはなりません。
- 同じ条件でシリアル接続中は、タブを閉じる・再読み込み・戻るで「このサイトを離れますか？」の確認が出ます。
- 右 ⌘ も Ctrl になるため、Win キー単体はショートカットの「Win」行から送ります。
- 英数/かな の変換をオンにすると、押したキーはホスト側の IME も切り替えます（ホストと操作先が揃うので実害はありません）。
- 貼り付けでは、Windows の操作先にテキストより先に IME オフキー（LANG2）を送るので、操作先の IME はオフになります（元に戻しません）。
- 操作先の Caps Lock がオンなら、貼り付けの前にオフにします（元に戻しません）。
- ブラウザー経由では、操作先で一時ウィンドウが開いて閉じ、操作先のクリップボードが上書きされます（「[クリップボードを入力（貼り付け）](#クリップボードを入力貼り付け)」の「ブラウザー経由の副作用」）。

## 既知の制限

- ⌘Tab、⌘Space、⌘Q、⌘⌥Esc、スクリーンショット系は macOS が先に処理するため送れません（ショートカットメニューを使ってください）。⌘W/T/N/⇧[ ] などは全画面＋キーボードロック時のみ届きます。
- 日本語など（ASCII 以外）は、Windows ではブラウザー経由、Linux では Ctrl+Shift+U で入力します。操作先 OS が macOS のときは入力せず、「入力できない文字」として報告します（どちらの方法も Ctrl のショートカットを使うため。⌘ を使う macOS 向けの方法は未実装）。US / JIS は操作先の設定に合わせる必要があります。
- Windows の Alt+テンキーによる文字コード入力（Alt コード）は使いません。既定の（新しい）Microsoft IME では 255 を超える値が下位 1 バイトに切り詰められ、RichEdit 系のアプリは値を CP932 ではなく Unicode として読み、NumLock がオフだとテンキーの数字が Alt+←/→/Home（ブラウザーの戻る / 進む / ホーム）として届くためです。
- ブラウザー経由はテキスト全体を 1 つの URL で送ります（分割しません）。長いほど時間がかかり（日本語 2,000 文字で標準約 5 分半）、途中で止まると最初からやり直しです。
- ブラウザー経由で直接貼り付けられるのは、ブラウザーの中の欄だけです。映像が必要で、HDMI に映らない画面では使えません。
- 自動でオフにした Caps Lock は元に戻しません。IME オフキーでオフにした IME も戻しません。
- Caps Lock の補正は「macOS がロックオンで keydown、オフで keyup を出す」前提です。操作先と 2 回ずれるような挙動なら、チェックを外してください。macOS の「Caps Lock で入力ソースを切り替える」設定とは相性がよくありません。
- 「英数/かな → 無変換/変換」は MS-IME に IME オフ/オン を割り当てている場合にだけ意味があります（既定ではオフ）。Windows 10 2004 以降 / 11 の日本語キーボードなら、オフのままで 英数/かな が IME オフ/オン として働きます。
- 機器（CH9329）から読むのは、貼り付けの前の Caps Lock の状態だけです。ホストと操作先の Caps Lock / NumLock の同期（LED 同期）や、キーごとに応答（ACK）を待って送る制御はしていません。
- 相対座標モードはポインターロック（Chrome）が前提で、Esc で解除されます。
- HID ログに出るのは、送信したキーボードとマウスのレポートだけです（機器の応答と、Caps Lock の状態を読む GET_INFO は出ません）。

## upstream からの挙動変更

設定を何も触らないユーザーにも影響する変更です（spec §8 ＋ このフォーク独自の既定値）。

- **Mac ホストでは ⌘ が既定で Ctrl として送られます**（upstream: ⌘ = Win）。キーボード → ⌘ キー変換 → オフ で upstream と同じキーボードのバイト列になります。操作先 OS を macOS にしても無効になります。有効かつシリアル接続中はタブを閉じるときに確認が出ます。
- スクロールが 1 イベント 1 ノッチではなく移動量に比例するようになりました（px 積算＋最初のノッチの即発火）。
- 絶対座標モードは Pointer Events とポインターキャプチャを使うため、動画の外で離してもボタンが押しっぱなしになりません。フォーカス喪失・タブ非表示でもボタンを離します。
- 右端・下端の座標が 4095 になります（upstream は 4096 を送っていました）。
- 相対座標モード: 小さい移動量を 2 倍にするルールを廃止（代わりにポインター速度スライダー）、ロック中以外は何も送らない（ロック取得のクリックが操作先に届かない）、大きな移動は分割して全距離を送る、ロック解除でボタンを離す。
- マウスの移動レポートはシリアル書き込み中に間引かれます（絶対座標は最新を優先、相対座標は合算）。ボタン・ホイール・解除は捨てません。キーボードは対象外です。
- マウスジグラーが実際に動くようになりました（相対マウスのコマンドで送信）。
- 貼り付けは 20 ms / 20 ms のペースで、進捗・キャンセル・強制停止つきになりました（upstream は 50 ms 押下のみで止められませんでした）。JIS の変換表は「操作先のキー配列」が JIS のときだけ使われます。キー配列で打てない文字（日本語など）は、Windows ではブラウザー経由、Linux では Ctrl+Shift+U で入力します。macOS では黙って捨てずに報告します。
- 貼り付けでは、Windows の操作先にテキストより先に IME オフキー（LANG2）を送ります。操作先の Caps Lock がオンなら、先にオフにします。
- シリアルの受信を常に読み取るようになりました（upstream は機器の応答を読まずに溜めていました）。貼り付けの前には（「操作先の Caps Lock がオンなら自動でオフにする」がオンなら）、Caps Lock の状態を読む GET_INFO（`57 AB 00 01 00 03`）を機器に送ります。機器への問い合わせなので、操作先には何も届きません。
- 日本語のブラウザーでは UI が日本語になります。

それ以外のレポートは upstream とバイト単位で同一です（パリティテストで検証）。

## 仕様書との相違点

- `DEFAULT_REMAP_CONFIG.enabled` は `true`（仕様書 §3.1/§3.2 は `false`）。
- 初回バッジは実装していません（`nanokvm-usb-keyboard-remap-seen` キー、青い点、`badgeTip` 文字列はありません）。

### HID ログ（`?debug=hid`）

`http://localhost:3001/?debug=hid` で開くか、キーテスト（キーボード → ⌘ キー変換 → 送信できるショートカット）右下の「HID ログ」をクリックすると、左下に送信レポートのパネルが出ます。

```
 +Δt  種別  バイト列                  デコード
  +0  kb    01 00 00 00 00 00 00 00  Ctrl
 +12  kb    01 00 06 00 00 00 00 00  Ctrl + C
 +50  kb    01 00 00 00 00 00 00 00  Ctrl
+180  kb    00 00 00 00 00 00 00 00  (none)
  +8  abs   02 00 ff 0f 00 08 ff     x=4095 y=2048 btn=- whl=-1
  +9  rel   01 01 7f 00 00           dx=127 dy=0 btn=L whl=0
```

- `kb` = 8 バイトのキーボードレポート、`abs` = 絶対座標のペイロード（x/y は 0〜4095）、`rel` = 相対座標のペイロード（符号つき int8）。`+Δt` は直前のレポート（種別を問わず）からの ms。
- 表示は最新 12 件、バッファーは 200 件。「コピー」で全件をテキストでコピー、「クリア」で消去。書き込みに失敗したレポートは赤で表示されます。
- × を押すと閉じて `nanokvm-usb-debug-hid` を解除します。URL に `?debug=hid` が付いていれば次回も表示されます。
- 記録はパネルが閉じていても常に行われているので、開いた直後から直前の履歴を見られます。
