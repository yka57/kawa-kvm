# Spec v2 — Japanese (non-ASCII) paste, IME-off key, Caps Lock pre-flight

Owner spec, 2026-11-03. Implementers: do not edit this file; if the code cannot follow it, say so in your
report. v1 (`docs/spec-v1.md`) still applies wherever this file is silent. The user asked for Japanese text
copied on the Mac to be typed into the target (v1 typed ASCII only and listed Japanese as skipped).

## 0. Ground truth (research of 2026-11-03; sources in the research log, key ones inline)

- Only CH9329 keyboard reports (cmd 0x02: modifier byte, 0, six usages) reach the target. Nothing can be
  installed there. There is no HID Unicode.
- Windows Alt+numpad codes are NOT used: under the default (new) Microsoft IME, Alt+decimal above 255 is
  reduced to its low byte (systematic but anecdotal test, zenn.dev/haretokidoki), RichEdit apps read the
  value as Unicode instead of CP932, and with NumLock off the keypad digits arrive as Alt+Left/Right/Home
  (browser Back/Forward/Home).
- HID LANG2 (0x91) → scan F1 → `VK_IME_OFF` on Windows 10 1903 (18362.1049+), 2004 (19041.388+) and later and
  on Windows 11 with the Japanese layout: Microsoft IME goes to half-width alphanumeric (IME off) from any
  state, repeat-safe, ignored by older builds (learn.microsoft.com … keyboard-japan-ime). LANG1 (0x90) is
  `VK_IME_ON`. 無変換 (0x8B) does NOT turn Microsoft IME off by default (it cycles the kana type). The CH9329
  key table lists 0x90/0x91.
- Typed `data:` URLs are top-level navigations in Chrome, Edge and Firefox (only renderer-initiated data:
  navigations are blocked). Chrome never sends inputs whose scheme is not http/https/ftp to the suggest
  server, and Incognito disables suggest; but Chrome/Edge store typed data: URLs in history (private windows
  avoid that). Ctrl+W on the only tab of a new window closes it; the OS reactivates the previous window and
  the browser restores its focused element. Edge's new-tab page may route typing to its Bing box: always
  press Ctrl+L first. Escape in an unedited Chromium omnibox focuses the page.
- Linux: Ctrl+Shift+U, hex digits, Space is handled by IBus ≥ 1.5.19, fcitx5 ≥ 5.0.20 (DirectUnicodeMode),
  GTK's GtkIMContextSimple and Chromium's CharacterComposer. Hex is case-insensitive, one code point per
  sequence, Space commits (it fails safe; Enter could submit a form). Under IBus with Mozc in hiragana mode
  the digits are eaten; GTK/Chromium refuse to start while Caps Lock is on; terminals without an IM receive
  ^U.
- The NanoKVM-USB HID side is a stock CH9329 (V1.8). Every command gets a reply frame (keyboard
  `57 AB 00 82 01 00 85`). GET_INFO request `57 AB 00 01 00 03`, reply `57 AB 00 81 08 ver usb led 0 0 0 0 0
sum`: `usb` = 0x01 when the target enumerated the device, `led` bit0 Num, bit1 Caps, bit2 Scroll (only
  meaningful when usb = 0x01). V1.8 also pushes unsolicited 0x81 frames about 15 ms after the target changes
  its LEDs. Error replies are `cmd | 0xC0` with one status byte (E1–E6). Checksum = low byte of the sum of
  every byte from 0x57 through the last data byte. Upstream never reads replies: they pile up unread, the
  upstream `getInfo()` reads stale acks, its checksum loop skips the last data byte, and racing
  `reader.read()` against a timeout leaves a pending read that later swallows a chunk.

## 1. User-visible behaviour

1. A text the direct path can type completely (after the v1 punctuation folding when `normalizePunct` is on)
   is typed as in v1, with two additions: the IME pre-key default is now `auto` = LANG2 on Windows targets
   (§2), and the Caps Lock pre-flight (§8.3) runs first.
2. Otherwise (at least one grapheme has no key in the target layout table) the resolved Unicode method
   decides:
   - `bridge` (default for Windows targets): the whole text, ASCII included, travels through the target
     browser (§4). Byte-exact: no punctuation folding, no NFC.
   - `ctrl-shift-u` (default for Linux targets): characters with a key are typed directly, every other code
     point through Ctrl+Shift+U (§5). No folding, no NFC.
   - `skip` (macOS targets, or chosen explicitly): v1 behaviour, non-typable characters are skipped and
     listed.
3. The first bridge run in a browser profile shows a one-time explanation with the ETA (§9.2).
4. While a bridge run is in progress the pill shows the phase and 「完了まで操作しないでください」.

## 3. Planning (`src/libs/paste/plan.ts`, pure)

```ts
export interface PlanOptions {
  layout: TargetLayout;
  newline: NewlineMode;
  normalizePunct: boolean;
  stripTrailingNewline: boolean;
  imePreKey: ImePreKey;
  method: UnicodeMethod;
  maxChars: number;
}
export type PastePlan =
  | { kind: 'direct'; compiled: CompileResult }
  | { kind: 'unicode'; compiled: CompileResult } // Ctrl+Shift+U strokes (§5)
  | { kind: 'bridge'; text: string; stats: CompileStats; skipped: SkippedChar[] };
export function planPaste(text: string, o: PlanOptions): PastePlan;
export function prepareRawText(
  text: string,
  o: { stripTrailingNewline: boolean; maxChars: number }
): { text: string; graphemes: string[]; skipped: SkippedChar[]; stats: CompileStats };
```

1. `direct = textToKeySequence(text, {...o})` (v1 compiler, with folding/NFC as configured).
2. If `direct.skipped` has no entry with reason `'no-key'`, or `o.method === 'skip'` → `{kind:'direct'}`.
3. Otherwise `prepareRawText`: strip a leading BOM, fold CRLF and lone CR to LF, NO NFC, NO punctuation
   folding; drop one trailing `\n` when `stripTrailingNewline`; segment graphemes (`segmentGraphemes`); graphemes
   beyond `maxChars` → skipped `'limit'` (`truncated`); C0/C1 controls other than `\n` and `\t` → skipped
   `'control'` and removed. `stats.chars` = graphemes after the trailing-newline strip, `typed` = graphemes
   kept, `skipped` = skipped entries. `text` = the kept graphemes joined.
4. `method === 'ctrl-shift-u'` → `{kind:'unicode', compiled: compileUnicode(prepared, o)}` (§5).
5. `method === 'bridge'` → `{kind:'bridge', text: prepared.text, stats, skipped}`.

`decideStart` keeps working on `stats` (typed 0 → nothing; chars above the soft limit → confirm).

## 4. Browser bridge (`src/libs/paste/bridge.ts`)

### 4.1 Payload (pure)

```ts
export const BRIDGE_URL_PREFIX = 'data:text/html;charset=utf-8;base64,';
export const BRIDGE_PROBE_URL = 'data:text/html,<body bgcolor=magenta>';
export function bridgeHash(value: string): number; // h = 0; for each UTF-16 unit c: h = (h * 31 + c) | 0
export function buildBridgeHtml(value: string): { html: string; hash: number };
export function utf8Base64(s: string): string; // UTF-8 bytes, standard alphabet, no line breaks
export function buildBridgeUrl(value: string): string; // BRIDGE_URL_PREFIX + utf8Base64(html)
```

`value` is the prepared text (LF only, no controls but `\t`/`\n`). `escaped` = value with `&` → `&amp;` and
`<` → `&lt;`, plus one extra leading `\n` when value starts with `\n` (the parser drops one). Exactly:

```
<textarea id=t autofocus>{escaped}</textarea><script>for(v=t.value,h=i=0;i<v.length;)h=h*31+v.charCodeAt(i++)|0;document.bgColor=h=={hash}?'lime':'red'</script>
```

followed by 0–2 spaces so the UTF-8 length is a multiple of 3 (the URL then never ends in `=`). Colours must be
names (legacy colour parsing turns `0f0` into a near-black). `bridgeHash` and the page script must agree
for every string, including astral characters, `</textarea>` inside the text and a leading newline: a test
runs the generated script against a stub `t`/`document`.

### 4.2 Program (pure builder; sampler and stroke helpers injected)

```ts
export interface BridgeDeps {
  sampler: FrameSampler; // §7
  layout: TargetLayout;
  imeOff: ImePreKey; // resolved; 'none' sends nothing
  window: BridgeWindow;
  probe: boolean; // type the probe page first
  onProbeOk(): void; // the controller caches the success (§9.3)
}
export const BRIDGE_TIMING = {
  pollMs: 100,
  windowTimeoutMs: 4000,
  windowSettleMs: 600,
  focusSettleMs: 150,
  imeSettleMs: 150,
  probeTimeoutMs: 5000,
  loadTimeoutBaseMs: 5000,
  loadTimeoutPer2kCharsMs: 1000,
  copySettleMs: 250,
  closeTimeoutMs: 3000,
  closeSettleMs: 300
};
export function buildBridgeProgram(url: string, deps: BridgeDeps): ProgramStep[];
```

Chords (one report with modifier + key, then the all-zero release; never a modifier-only report):
open window = Ctrl+Shift+N (`chromium-private`), Ctrl+Shift+P (`firefox-private`), Ctrl+N (`new-window`);
Ctrl+L, Ctrl+A, Ctrl+C, Ctrl+W, Ctrl+V; Delete (0x4C), Enter (0x28), Escape (0x29); IME off = the resolved
pre-key (LANG2 0x91 or 無変換 0x8B) with `afterMs: imeSettleMs`. URL text is compiled with the layout table
(every URL character must have a key; throw if not — programming error).

Steps:

1. phase `window`; run: `base1 = sampler.sample()`.
2. keys: open-window chord.
3. wait: `changedFraction(base1, now) >= WINDOW_CHANGE_MIN` → ok; timeout `windowTimeoutMs` →
   stop `'bridge-no-window'`. Nothing else has been typed at this point.
4. sleep `windowSettleMs`; run: `base2 = sampler.sample()`.
5. keys: Ctrl+L (`afterMs: focusSettleMs`), IME off (if any).
6. Only when `probe`: phase `probe`; keys: probe URL, Delete, Enter; wait: magenta present vs `base2`
   (`probeTimeoutMs`, timeout → stop `'bridge-probe-failed'`; never send Ctrl+W here); run `onProbeOk()`;
   keys: Ctrl+L (`afterMs: focusSettleMs`), IME off (if any).
7. phase `type`; keys: the payload URL, Delete, Enter.
8. phase `verify`; wait, per poll: lime present vs `base2` → ok; red present → fail; timeout
   `loadTimeoutBaseMs + ceil(url.length / 2000) * loadTimeoutPer2kCharsMs` → stop `'bridge-load-failed'`.
   Fail → send `onFail` = [Ctrl+W] (the red page is ours, so closing it is safe), stop
   `'bridge-verify-failed'`.
9. phase `copy`; keys: Escape, Ctrl+A, Ctrl+C (`afterMs: copySettleMs` on Ctrl+C).
10. phase `close`; keys: Ctrl+W; wait: lime gone vs `base2` (`closeTimeoutMs`, timeout → stop
    `'bridge-close-failed'`); sleep `closeSettleMs`.
11. phase `paste`; keys: Ctrl+V.

Estimates for the ETA: window 800 ms, probe load 700 ms, payload load 800 ms, close 500 ms.

## 5. Ctrl+Shift+U (`src/libs/paste/unicode-entry.ts`, pure)

```ts
export const UNICODE_TRIGGER_SETTLE_MS = 80; // after the trigger's release
export const UNICODE_FIRST_TRIGGER_SETTLE_MS = 400; // first trigger of a run (IBus loads its data lazily)
export const UNICODE_COMMIT_SETTLE_MS = 80; // after the Space
export function codePointStrokes(
  cp: number,
  src: number,
  group: number,
  first: boolean
): KeyStroke[];
export function compileUnicode(
  prepared: ReturnType<typeof prepareRawText>,
  o: PlanOptions
): CompileResult;
```

`codePointStrokes`: [Ctrl+Shift+U (mod LeftCtrl|LeftShift, KeyU, tag `'unicode'`, afterMs trigger settle or
first settle)], then `cp.toString(16).padStart(4, '0')` lowercase, each digit a main-row key (`Digit0`–`Digit9`,
`KeyA`–`KeyF`, never the keypad, mod 0, tag `'unicode'`), then Space (tag `'unicode'`, afterMs commit settle).
All strokes of one code point share `group`. `compileUnicode`: optional ime-pre stroke first (as in v1, now
with `afterMs: 150`), then per grapheme `\n` → Enter (newline mode), `\t` → Tab, a layout-table hit → its
direct stroke, otherwise one group per code point of the grapheme (`for (const ch of grapheme)`). Stats as in
§3; `typed` counts graphemes.

## 6. Typing engine program (`src/libs/paste/typing-engine.ts`)

`KeyStroke` (types.ts) gains `afterMs?: number` (extra pause after this stroke's gap) and `group?: number`
(atomic group); `StrokeTag` gains `'unicode' | 'chord'`. The v1 compiler gives the ime-pre stroke
`afterMs: 150` (`IME_SETTLE_MS`).

```ts
export type PastePhase = 'window' | 'probe' | 'type' | 'verify' | 'copy' | 'close' | 'paste';
export type WaitVerdict = 'ok' | 'pending' | 'fail';
export type ProgramStep =
  | { kind: 'keys'; strokes: KeyStroke[] }
  | { kind: 'sleep'; ms: number }
  | {
      kind: 'wait';
      check(): WaitVerdict | Promise<WaitVerdict>;
      timeoutMs: number;
      intervalMs?: number /*100*/;
      estimateMs: number;
      timeoutReason: StopReason;
      failReason?: StopReason;
      onFail?: KeyStroke[];
    }
  | { kind: 'run'; fn(): void }
  | { kind: 'phase'; phase: PastePhase };
export type StopReason =
  | /* v1 values */ 'bridge-no-window'
  | 'bridge-probe-failed'
  | 'bridge-load-failed'
  | 'bridge-verify-failed'
  | 'bridge-close-failed'
  | 'caps-lock';
class TypingEngine {
  runProgram(
    steps: ProgramStep[],
    pacing: Pacing
  ): Promise<EngineResult>; /* run(compiled) = runProgram([{kind:'keys', strokes}]) */
}
```

- ARM and FINISH are unchanged (lock, interrupt listeners, ZERO first, ZERO last, listeners off, lock
  released, `stop` event). `run(compiled, pacing)` must behave exactly as in v1 for v1 inputs.
- Keys: press, hold, release (all-zero), then sleep `gapMs + (enter ? afterEnterMs : 0) + (afterMs ?? 0)`;
  no sleep after the very last stroke of the whole program.
- `done`/`total` count strokes of `keys` steps (not `onFail`). `etaMs` = remaining stroke durations + remaining
  sleeps + remaining waits' `estimateMs`. Events carry `phase` (the latest `phase` step).
- `wait`: poll `check()` (an exception counts as `'pending'`) every `intervalMs` until `'ok'` (next step),
  `'fail'` (send `onFail` strokes best-effort, then stop with `failReason`) or the deadline (stop with
  `timeoutReason`). A cancel aborts the wait at once.
- `run`: call `fn()`; an exception is logged and the program continues.
- The watchdog only runs while keys are being sent; it is cleared during `sleep`, `wait` and `run` and
  re-armed by the next send.
- Atomic groups: while the program is between the first press and the last release of a group, `cancel()`
  with any reason except `'serial-error'` is DEFERRED (first reason kept, the lock stays held, nothing is
  woken); it takes effect right after the group's last stroke. `'serial-error'` (including the watchdog and
  write timeouts) is never deferred.

## 8. Device replies and lock state

### 8.1 `src/libs/device/frame-parser.ts` (pure)

`class FrameParser { push(bytes: ArrayLike<number>): ParsedFrame[]; reset(): void }`,
`ParsedFrame { addr: number; cmd: number; data: number[] }`. Finds `57 AB`, waits for `6 + LEN` bytes, requires
`LEN <= 64` and a valid checksum (§0); on any mismatch drops one byte and resyncs. Frames may be split across
chunks.

### 8.2 `src/libs/device/serial-port.ts`

One persistent read loop per open port, started in `init()`: `reader.read()` in a loop, every chunk fed to a
`FrameParser`, frames dispatched to `onFrame(listener): () => void` subscribers (a throwing listener is
isolated). Exactly one outstanding `read()` at any time. The loop ends on `done`, on `close()` (reader
cancel) and on errors: a disconnect error goes through the existing `handleDisconnect()` once; errors from a
reader that was already released or replaced are ignored. The parser resets on init/close. The old
`read(minSize)` (only caller: upstream `getInfo`) is removed.

### 8.3 `src/libs/device/index.ts`

```ts
export interface LockState { num: boolean; caps: boolean; scroll: boolean; version: number }
getLockState(timeoutMs = 300): Promise<LockState | null>;
```

Writes GET_INFO (not added to the HID log) and resolves with the first 0x81 frame received after the write;
a 0xC1 error or a timeout retries once; null when there is no answer or when `usb !== 0x01`. Unsolicited 0x81
frames update a cached `LockState` (no API needed beyond that). Upstream `getInfo()` is removed (no callers);
`InfoPacket`/`CmdPacket` may stay unused. Concurrent calls share one in-flight request.

Caps Lock pre-flight (controller, all three paths): when `fixCapsLock` and `getLockState()` reports
`caps: true`, the program starts with keys [toggle] — JIS layout: Shift+CapsLock (mod LeftShift, 0x39, because
a bare 0x39 is 英数 on JIS targets); US: bare 0x39 — then a wait that polls `getLockState()` (ok when
`caps === false`, timeout 1000 ms → stop `'caps-lock'`). Unknown state (null) → no pre-flight. Caps Lock is
not restored afterwards.

## 9. Controller (`src/components/menu/keyboard/paste/controller.ts`)

### 9.1 Flow

`start()` keeps the v1 order (busy → pending → serial → clipboard → empty) and then:

1. `settings` normalised; `targetOs` from `targetOsAtom`; `method = resolveUnicodeMethod(...)`;
   `imePreKey = resolveImePreKey(...)`; `plan = planPaste(source, …)`.
2. `decideStart` on the plan's stats (`nothing`, `notConnected`, `confirm` above the soft limit, `run`).
3. Bridge only: `sampler.available()` false → notice `noVideo`, outcome `'noVideo'`, nothing sent. Otherwise,
   if the intro was never accepted (storage `nanokvm-usb-paste-bridge-intro`), `ui.confirmBridge(seconds)`;
   declined → `'declined'`; accepted → store the flag.
4. Large-paste confirm as in v1 (ETA from the program, §6).
5. Caps Lock pre-flight (§8.3), then `engine.runProgram(steps, PACING[speed])`.

### 9.2 UI bridge

`PasteUi` gains `confirmBridge(seconds: number): Promise<boolean>`, implemented next to `confirmLarge`
(antd Modal.confirm, title `paste.bridgeIntroTitle`, content `paste.bridgeIntro`).

### 9.3 Probe cache

In memory only: the probe runs when the key `layout|bridgeWindow|imePreKey(resolved)|targetOs` differs from
the last key whose probe succeeded (`onProbeOk`). A page reload probes again.

### 9.4 Run state

`PasteRunState` gains `phase?: PastePhase` and `method?: 'direct' | 'unicode' | 'bridge'`. New stop reasons
map to the i18n keys below; `resyncDriver` behaviour unchanged.

## 14. Owner addendum (2026-11-04, after the adversarial review) — overrides the sections above

1. **Probe every run** (replaces §9.3 and step 6's `probe` flag): the probe is the only proof that typing reaches
   a browser address bar with the right layout before user data is typed. `BridgeDeps.probe`/`onProbeOk` and the
   controller's probe cache are removed.
2. **Case-sensitive probe** (replaces `BRIDGE_PROBE_URL`):
   `data:text/html,<body bgcolor=red><script>document.bgColor='magenta'</script>`. Under Caps Lock the script
   fails (`DOCUMENT` is undefined) and the page stays red. Probe wait: magenta present → ok; red present → fail
   with `onFail` [Ctrl+W] (the red page is ours) and stop `'bridge-probe-red'`; timeout → `'bridge-probe-failed'`
   (no Ctrl+W).
3. **Still screen before anything is sent** (replaces step 1): wait A — a non-null frame (timeout 1000 ms →
   `'bridge-no-video'`); wait B — two samples about 300 ms apart (`intervalMs` 300) with
   `changedFraction < SCREEN_STILL_MAX = 0.02`; the later one is `base1` (timeout 2500 ms → `'bridge-busy-screen'`).
   Only then the open-window chord. The controller re-checks `sampler.available()` right before launching.
4. **Copy confirmation**: the payload script becomes
   `d=document;for(v=t.value,h=i=0;i<v.length;)h=h*31+v.charCodeAt(i++)|0;d.bgColor=h=={hash}?'lime':'red';oncopy=e=>{e.clipboardData.setData('text',v);e.preventDefault();d.bgColor='blue'}`
   (same textarea, escaping, padding and hash rules). After Escape, Ctrl+A, Ctrl+C: wait for blue present vs
   `base2` (timeout `copyTimeoutMs` 1500 → `'bridge-copy-failed'`, no Ctrl+W, no Ctrl+V). `copySettleMs` is no
   longer needed after Ctrl+C. New sentinel `blue`: `b >= 150 && r <= 90 && g <= 90` (disjoint from the others).
5. **Close check against the screen before the window** (replaces step 10's wait): ok only when
   `sentinelGone(now, base1, 'blue')` and `changedFraction(base1, now) < WINDOW_CHANGE_MIN`; timeout
   `closeTimeoutMs` → `'bridge-close-failed'`, never Ctrl+V.
6. **Deferral only for input that never reaches the target** (replaces the atomic-group rule of §6): only
   `'cancelled'` and `'key-interrupt'` are deferred inside a group. `'mouse-interrupt'` (the click is forwarded to
   the target) and `'tab-hidden'` (background timer throttling would hold keys about 1 s and autorepeat; pagehide
   could leave a key down) stop at once, like `'serial-error'`. A deferred cancel that would take effect after the
   program's last stroke is dropped: the run ends `'completed'`.
7. **Mouse quiet while the HID lock is held**: the absolute, relative and touch paths drop wheel reports and
   pure-move reports while `hidLock.isLocked()`; button presses and releases still go through (a press stops the
   run as before; releases must never be lost).
8. **Serial read recovery**: after a non-fatal read error (BreakError, FramingError, ParityError,
   BufferOverrunError) WebSerial offers a new `port.readable`; the loop releases the old reader, resets the parser
   and continues on the new stream. `handleDisconnect` also resets the parser.
9. **Invisible characters**: with `normalizePunct`, the direct path also removes U+00AD, U+200B, U+200C, U+200D,
   U+2060 and U+FEFF, so they no longer send ASCII text through the bridge. Raw paths keep them.
